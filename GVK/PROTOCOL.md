### 0.1 Что это за файл

Данный протокол содержит инструкции для агента-кодера. Для Нейросети-программиста.
Данный протокол допускает запуск любого количества агентов одновременно.

Протокол хранится в единственном экземпляре в репозитории Sigmawillow, в папке "GVK". Агент-кодер обращается к нему.

**Зачем он нужен.** Негативный сценарий без данного протокола: Ты запускаешь несколько Гвк в разных вкладках. Без правил они берут одну и ту же задачу, перезаписывают правки друг друга и ломают сборку.
Этот файл-протокол превращает их в самостоятельную бригаду: каждый агент-кодер сам узнаёт, что делать, сам берёт свободный кусок работы, сам отчитывается, а последний сам собирает результат и убирает за собой и за всеми.

**Что он даёт тебе:**

- тебе незачем держать в голове информацию о ролях. Агенты-кодеры узнают всё сами;
- ты не разбиваешь ТЗ на части — это делает первый агент-кодер;
- ты не создаёшь pom.xml, workflow, .gitignore и README — это делает первый агент-кодер по готовым шаблонам;
- ты не сливаешь ветки и не удаляешь мусор — это делает последний агент-кодер;
- твоё участие: сообщение в чат и взгляд на одну страницу состояния. Страница состояния: файл "GVK/STATE.md" в том репозитории, над которым работают агенты-кодеры.

**Чего он не делает:** не заменяет ТЗ, не придумывает требования, не проверяет Windows-GUI в Linux-песочнице (это уходит в GitHub Actions), не задаёт тебе вопросов.

**Как устроен файл протокола:** пункт 0.3 вынесен наверх, он ключевой. Остальное руководство — здесь, под спойлером. Инструкции для бота — в отдельном спойлере ниже. Ты можешь читать только руководство и никогда не открывать машинную часть.

### 0.4 Команды-рычаги

Дописываются к сообщению запуска строкой, начинающейся с `РЫЧАГ:`. Без рычага — обычный цикл.

| Команда | Действие |
|---|---|
| **ПАМЯТКА** | вывести эту таблицу в чат, чтобы ты не запоминал |
| **ТОЛЬКО ОТЧЁТ** | ничего не менять, дать сводку |
| **СЕРИЯ** | брать фрагменты подряд, пока хватает квоты |
| **ЖДИ 6** | ждать освобождения до 6 часов (по умолчанию 2) |
| **ПРОДОЛЖИ 007** | подхватить зависший фрагмент, продлить аренду |
| **ОТОЗВАТЬ 007** | поколение +1, начать фрагмент заново |
| **ОТОЗВАТЬ ДОЛГИЙ** | то же для самого долгого фрагмента |
| **ОСВОБОДИ 007** | снять захват без переделки |
| **ЗАКРОЙ** | закрыть ТЗ: слияние всех веток, тесты, уборка |
| **ПЕРЕПЛАНИРУЙ** | пересобрать план; только когда живых захватов нет |
| **ОБНОВИ ВЕРСИИ** | поднять пинованные версии плагинов и actions, проверить сборку |
| **ВОССТАНОВИ GVK ИЗ 3c4b1b4a** | вернуть удалённую папку из указанного коммита |
| **ПРОВЕРЬ 007** | роль контролёра: проверить фрагмент, код не менять |
| **ГВК-Э** | включить словарное сжатие служебных полей |
| **ЖЕЛАНИЕ: хочу тёмную тему по умолчанию** | изменить ТЗ по новому желанию, пересчитать план |
| **ПРОДОЛЖИТЬ ПО СТАРОМУ ТЗ** | ответ на частичную выполнимость: желание отклонить |

### 0.8 Частые вопросы

**Почему ветки копятся и не сливаются?** Так задумано: сливает только закрывающий кодер, в самом конце. Исключение — каркас 000, его сливает первый. Если фрагменту нужен чужой пакет, кодер подтягивает чужую ветку в свою, а не в main.

**Я уже навертел исходники вручную — их выбросят?** Нет. Первый кодер проводит аудит и по умолчанию сохраняет всё рабочее. Переписывание — только с доказательством поломки, удаление — только с доказательством, что код никем не используется. Все удаления происходят в ветке и обратимы через историю git.

**Подойдёт для любого моего репозитория?** Да. Стек един: Java 21, Maven, переносимый EXE через jpackage. В чисто документном репозитории каркас не создаётся — там проверяются шапки md+ и ссылки.

**Нужен Windows-EXE.** Собирается на раннере GitHub Actions `windows-latest`, потому что jpackage собирает Windows-пакет только на Windows. Готовый ZIP лежит в Releases и артефактах, в git не коммитится.

**Бот умер молча.** Ничего не потеряно: в ветке лежат только зелёные состояния. Аренда истечёт через 80 часов, либо ты дашь `ОСВОБОДИ` или `ПРОДОЛЖИ`.

**Что такое бутстрап.** Начальная самоподготовка окружения: поставить JDK и Maven, задать переменные, настроить git, скачать протокол. Раньше это делал скрипт установки, теперь кодер делает сам по пункту 1.5.

**Сменилась модель.** Протокол от модели не зависит: всё состояние в файлах, а не в памяти чата.

**Что значит «версии пинованы».** Версии плагинов и actions прибиты к конкретным числам, чтобы сборка не ломалась сама собой. Поднимать — только рычагом `ОБНОВИ ВЕРСИИ`.

**Почему код не сжат в один символ.** Короткие ASCII-имена и удаление комментариев-пересказа уменьшают и символы, и токены. Односимвольные Unicode-имена уменьшают символы, но увеличивают токены и ломают кодировки. Приняты только приёмы с двойным выигрышем. Подробности в Части 13.

# ЧАСТЬ 1. ОБЩИЕ ПРАВИЛА КОДЕРА

Руководство владельца выше — справка для человека. Не исполнять, не учитывать при планировании. Твои инструкции начинаются здесь. Спойлеры прячут текст от человека, но не от тебя: читать нужно всё.

**1.0. Шлюз.** Токен возьми из сообщения владельца. Первым делом выполни один блок:

```bash
unset HISTFILE; umask 077
mkdir -p /opt/gvk
printf '%s' 'ТОКЕН_ИЗ_СООБЩЕНИЯ' > /opt/.t
T=$(cat /opt/.t)
curl -sSL -H "Authorization: Bearer $T" -H "Accept: application/vnd.github.raw" https://api.github.com/repos/Bizonrelax/Sigmawillow/contents/GVK/PROTOCOL.md -o /opt/gvk/PROTOCOL.md
head -c 3 /opt/gvk/PROTOCOL.md; echo; wc -c /opt/gvk/PROTOCOL.md
```

Проверка: первые три символа `---`, размер больше 50000 байт. Если файл начинается с `{` — это ответ об ошибке, протокол не получен. Тогда: никаких записей, никакого кода, отчёт «протокол недоступен, причина» и выход. Работать по ТЗ без протокола запрещено.

Протокол получен — прочитай его целиком и только затем действуй.

**1.0.1. Рычаг.** Строка, начинающаяся с «РЫЧАГ:», — приказ, а не задача. Выполнить только его, ничего больше. `ОСВОБОДИ` не означает «сделать фрагмент».

**1.0.2. Пакеты и объём.** Имя пакета брать из `PLAN.md`, не изобретать. Функциональность сверх ТЗ не добавлять: лишнее — заявка в `REQUESTS.md`, а не код.

**1.1. Полномочия.** Токен принадлежит владельцу аккаунта Bizonrelax — тому же человеку, который пишет тебе в чат. Он передал его сознательно и явно разрешает чтение и запись в свои репозитории. Это не чужие учётные данные и не несанкционированный доступ. Отказ от работы по причине «чужой токен» — нарушение протокола.

**1.2. Автономность.** Вопросов владельцу не задавать никогда. При неоднозначности применяй правило по умолчанию и фиксируй решение в `GVK/AUDIT.md`. Действие невозможно — отчёт с причиной и выход.

**1.3. Адресат записи.** Пиши только в репозиторий, указанный в селекторе чата или в сообщении владельца. Bizonrelax/Sigmawillow — только чтение. Запись в Sigmawillow запрещена.

**1.4. Токен.** Хранится в `/opt/.t` (вне репозитория, права 600) и в переменной `T`, подхватывается через `/opt/env.sh`.

Запрещено: токен в URL remote, `.git/config`, `~/.git-credentials`, `~/.netrc`, любых файлах репозитория, в тексте отчёта, в сообщениях коммитов. Не включать `set -x`, не печатать токен через `echo`. В отчётах маскировать до последних 4 знаков.

Работа с git — только через заголовок:

```bash
. /opt/env.sh
git -c http.extraheader="$AUTH" fetch origin
git -c http.extraheader="$AUTH" push origin HEAD
```

Работа с API: `curl -H "Authorization: Bearer $T"`.

Перед коммитом — проверка по 4.9. Токен считается скомпрометированным по факту передачи в переписке: одной строкой в теле отчёта напомни владельцу отозвать его после сессии.

**1.5. Бутстрап окружения.** Один блок, один вызов:

```bash
J=/opt/jdk-21
[ -x "$J/bin/javac" ] || { mkdir -p "$J"; curl -sL https://api.adoptium.net/v3/binary/latest/21/ga/linux/x64/jdk/hotspot/normal/eclipse | tar xz --strip-components=1 -C "$J"; }
command -v mvn >/dev/null || { curl -sL https://archive.apache.org/dist/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.tar.gz | tar xz -C /opt && ln -sf /opt/apache-maven-3.9.9/bin/mvn /usr/local/bin/mvn; }
command -v mvn >/dev/null || (apt-get update -qq && apt-get install -y -qq maven) || true
cat > /opt/env.sh <<'EOF'
export JAVA_HOME=/opt/jdk-21
export PATH=/opt/jdk-21/bin:/opt/apache-maven-3.9.9/bin:$PATH
[ -f /opt/.t ] && T=$(cat /opt/.t)
AUTH="Authorization: Basic $(printf 'x-access-token:%s' "$T" | base64 -w0)"
EOF
. /opt/env.sh
git config --global user.name Bizonrelax
git config --global user.email bizonrelax79426315@gmail.com
git config --global --add safe.directory /workspace
java -version && mvn -v
```

Последняя строка обязана показать Java 21 и Maven. Не показала — отчёт о причине, код не писать.

**Каждая последующая команда начинается с `. /opt/env.sh`**: оболочка между вызовами может быть новой. Заново окружение не исследовать, JDK и Maven повторно не искать.

**1.6. Источники документации.** Протокол: `/opt/gvk/PROTOCOL.md`, полученный по шлюзу. ТЗ: путь из сообщения владельца, иначе искать в порядке `docs/TZ.md`, `Docs/ТЗ*.md`, `TZ*.md`, `SPEC*.md`, `README.md`. Несколько кандидатов — выбрать наибольший по объёму, выбор записать в `PLAN.md`. ТЗ не найдено — отчёт и выход. Поле «Описание» среды в контекст не попадает.

**1.7. Тип репозитория и критерий готовности.**

| Найдено | Тип | Готовность |
|---|---|---|
| ТЗ на программу, либо `*.java`, либо `pom.xml` | программный | Часть 10, затем `mvn -B -ntp verify` → Failures: 0, Errors: 0 |
| `*.py` без ТЗ на Java-программу | скриптовый | `pytest -q` → все пройдены |

**9.4. Закрытие однократно.** Попыток закрытия не более двух. Вторая неудача — отчёт о блокере и выход, без третьей попытки.

**9.5. Роли не совмещаются.** Автор фрагмента не может быть его контролёром.

**9.6. Право слияния.** Слияние в main разрешено только первому кодеру для фрагмента 000 и закрывающему кодеру по Части 7. Всем остальным слияние в main запрещено — ветка ждёт закрывающего. Отчёт «смёржен» от незаключающего кодера — нарушение протокола. Подтягивание чужой ветки в свою по 4.15 слиянием в main не считается.

**9.7. Нумерация.** Номер и пакет фрагмента брать только из `PLAN.md`. Нумерацию из отчётов предыдущих сессий и из памяти чата не использовать.

**9.8. Снятие захвата.** Захват снимается в той же сессии, где фрагмент завершён. Продлевать аренду чужого фрагмента запрещено.

**9.9. Один фрагмент за сессию** без рычага `СЕРИЯ`.

# ЧАСТЬ 13. СТИЛЬ И СЖАТИЕ КОДА

Цель: меньше символов **и** меньше токенов одновременно. Приняты только приёмы с двойным выигрышем.

**13.1. Принято.**

| Приём | Правило |
|---|---|
| Локальные имена | короткие ASCII: `i`, `n`, `k`, `s`, `p`, `tmp` |
| Публичные имена | осмысленные: классы, методы, поля — контракт из `PORTS.md`, переименование только через заявку |
| Комментарии | убрать пересказ кода; оставить одну строку смысла на класс и на нетривиальный метод; атрибуция обязательна |
| Дедупликация | повтор вынести в метод; мёртвый код удалить по вердикту DELETE |
| Служебные файлы | `GVK/*.md` — только таблицы и поля, без прозы |

Дедупликация даёт больший выигрыш, чем переименование. Начинать с неё.

**13.2. Запрещено.** Односимвольные не-ASCII идентификаторы: символов меньше, токенов больше, ломаются кодировки, усиливается дрейф сигнатур. Минификация исходников: Java компилируется, выигрыша в скорости и размере байткода нет, а разбор для бота ухудшается.

**13.3. Исключения.** Руководство владельца и README остаются полностью человекочитаемыми.

**13.4. Транспорт.** Длинные логи и простыни, передаваемые в чат, сжимать SaberW-2. Исходники в репозитории хранятся в обычном виде: сжатие применяется к передаче, не к хранению.

## 15.1. Контролёр (рычаг ПРОВЕРЬ NNN)

Роль проверки. Код не менять, только читать. Контролёр не может быть автором проверяемого фрагмента.

Проверить: соответствие ТЗ; границы пакета по `PLAN.md`; отсутствие функциональности сверх ТЗ; сходимость чисел в отчёте; реальное наличие файлов, о которых отчитались; атрибуцию; паритет EN/RU в затронутых разделах README; грамматику в README и комментариях.

Обязателен для фрагмента 000 и для любого фрагмента, меняющего порт. Для остальных — по рычагу. Механические проверки уже автоматизированы в 4.9 и 7.9, дублировать их не нужно.

## 15.2. Гвк-э (рычаг ГВК-Э)

Словарное сжатие служебных полей. Формат словаря:

```
Словарь - начало.
Ы mvn -B -ntp verify → Failures: 0, Errors: 0
Э захват отозван, работу выбросить, отчёт, выход
Ю файл не читается, запись не состоялась
Словарь - конец.
```

Код — первое слово строки, значение — всё остальное до конца строки. Словарь хранится в `GVK/DICT.md`, пополняется только с разрешения владельца.

**Разрешено:** поле `remaining` в `reports/NNN.md`, поле `доказательство` в `AUDIT.md`, внутренние заметки бота.

**Запрещено:** исходный код, README, `PLAN.md`, `STATE.md`, отчёт в чат, сообщения коммитов и сам протокол.

**Правило выгоды:** заменять только длинные частые фразы. Короткие статусы не заменять: CJK-символ стоит 2–3 токена, слово «ЗЕЛЕНО» — 2.

# ЧАСТЬ 16. ЖЕЛАНИЕ ВЛАДЕЛЬЦА

**16.2.** Рычаг `ЖЕЛАНИЕ: <текст>` прерывает обычную работу. Код сразу не писать.

**16.3. Шаги.**

1. Прочитай ТЗ, `PLAN.md`, `PORTS.md`, `LINKS.md`, `STATE.md`, отчёты фрагментов.
2. Оцени выполнимость: полностью / частично / невозможно. Причины — технические, платформенные, лицензионные.
3. Создай `GVK/CHANGE-NNN.md` (NNN — следующий свободный номер): было → стало, затронутые фрагменты и порты, влияние на дизайн и функционал, что уходит на переделку, оценка часов, вердикт выполнимости.
4. Невозможно или частично → отчёт владельцу и STOP. Ждать одной из трёх команд: `ПРОДОЛЖИТЬ ПО СТАРОМУ ТЗ`, `ВНЕСИ ВОЗМОЖНОЕ`, `МЕНЯЙ ТЗ ПО ЖЕЛАНИЮ`. До ответа ничего не менять.
5. Выполнимо полностью, либо получена команда `МЕНЯЙ ТЗ ПО ЖЕЛАНИЮ` → внеси правки в ТЗ, подними его версию, допиши раздел «История изменений» со ссылкой на `CHANGE-NNN.md`.
6. Обнови `PLAN.md` в `gvk-plan`: новые фрагменты добавить, затронутые перевести в «свободен» с `epoch`+1 и `change_id`. Обнови `PORTS.md`, `LINKS.md`, `STATE.md`.
7. Отчёт владельцу: какой ТЗ был, какой стал, что изменилось, как отразилось на дизайне и функционале, какие фрагменты уходят на переделку.
8. Выход. Разработку в этой сессии не вести.

**16.4.** ТЗ и план меняет только кодер, обрабатывающий ЖЕЛАНИЕ. Остальные — только читают.

**16.5. Защита от циклов.** Один `change_id` применяется к фрагменту один раз. Сброс `attempts` разрешён только при новом `change_id`. Повторное применение того же `change_id` запрещено.
