Эта часть написана обычным человеческим языком. Правила сжатия из Части 13 к ней не применяются.

### 0.1 Что это за файл

Это инструкция для кодеров, а не для тебя. Один файл лежит в Sigmawillow и обслуживает все твои репозитории — и существующие, и те, что ты создашь потом.

**Зачем он нужен.** Ты запускаешь несколько Гвк в разных вкладках. Без правил они берут одну и ту же задачу, перезаписывают правки друг друга и ломают сборку. Этот файл превращает их в самостоятельную бригаду: каждый сам узнаёт, что делать, сам берёт свободный кусок работы, сам отчитывается, а последний сам собирает результат и убирает за собой.

**Что он даёт тебе:**

- ты не помнишь ни номеров, ни ролей, ни количества кодеров — они узнают всё сами;
- ты не разбиваешь ТЗ на части — это делает первый кодер;
- ты не создаёшь pom.xml, workflow, .gitignore и README — это делает первый кодер по готовым шаблонам;
- ты не сливаешь ветки и не удаляешь мусор — это делает последний кодер;
- твоё участие: две строки в чат и взгляд на одну страницу состояния.

**Чего он не делает:** не заменяет ТЗ, не придумывает требования, не проверяет Windows-GUI в Linux-песочнице (это уходит в GitHub Actions), не задаёт тебе вопросов.

**Как устроен файл:** Часть 0 — эта справка, для тебя. Части 1–14 — машинные инструкции, для бота. Ты можешь читать только Часть 0 и никогда не открывать остальное.

### 0.2 Один раз на проект: настройка среды кодера

Открой настройки окружения в coder.qwen.ai и заполни четыре места.

**Первое. Организация и репозиторий.** Выбери Bizonrelax и нужный репозиторий. Имя среды — любое, например имя репозитория.

**Второе. Переменные среды.** Добавь одну переменную: имя `GH_TOKEN`, значение — твой токен GitHub. Токен лучше делать fine-grained: запись в целевой репозиторий, чтение в Sigmawillow. Больше нигде токен не появляется — ни в чате, ни в файлах.

**Третье. Скрипт установки.** Вставь этот текст целиком (881 символ, лимит 1000):

```bash
set -e
J=/opt/jdk-21
[ -x $J/bin/javac ] || { mkdir -p $J; curl -sL https://api.adoptium.net/v3/binary/latest/21/ga/linux/x64/jdk/hotspot/normal/eclipse | tar xz --strip-components=1 -C $J; }
command -v mvn >/dev/null || (apt-get update -qq && apt-get install -y -qq maven) || true
mkdir -p /opt/gvk
printf 'export JAVA_HOME=%s\nexport PATH=%s/bin:$PATH\n' $J $J > /opt/env.sh
. /opt/env.sh
git config --global user.name Bizonrelax
git config --global user.email bizonrelax79426315@gmail.com
git config --global --add safe.directory /workspace
curl -sL -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github.raw" https://api.github.com/repos/Bizonrelax/Sigmawillow/contents/GVK/PROTOCOL.md -o /opt/gvk/PROTOCOL.md || true
command -v gh >/dev/null && printf '%s' "$GH_TOKEN" | gh auth login --with-token || true
java -version && mvn -v && wc -c /opt/gvk/PROTOCOL.md
```

Он ставит JDK 21 и Maven, создаёт `/opt/env.sh`, настраивает git и скачивает этот протокол в `/opt/gvk/PROTOCOL.md`. Последняя строка печатает версии и размер протокола — по ним видно, что среда собралась. Это экономит примерно десять вызовов в каждой сессии.

**Четвёртое. Описание.** Поле для твоих заметок. Проверено: бот его содержимое не видит, поэтому документацию туда класть бесполезно. ТЗ должно лежать в репозитории, например `docs/TZ.md`.

### 0.3 Каждый запуск

**Сначала выбери репозиторий и ветку main в селекторе нового чата.** Без репозитория кодер уходит в режим создания сайтов и протокол не работает.

Потом отправь это сообщение. Токен не нужен — он уже в среде.

```
Репозиторий: Bizonrelax/PrimeWalker-2
Протокол: /opt/gvk/PROTOCOL.md; если файла нет — GVK/PROTOCOL.md из Bizonrelax/Sigmawillow через API, токен в $GH_TOKEN.
Протокол не получен — ничего не менять, доложить и выйти.
```

Нужен рычаг — добавь четвёртую строку, например `РЫЧАГ: ПРОДОЛЖИ 001`. Слово `РЫЧАГ:` обязательно: без него бот принимает приказ за описание задачи.

Сколько кодеров запускать — решаешь ты. По умолчанию один кодер берёт один фрагмент.

### 0.7 Чего не делать

Не создавать ветки руками. Не править план руками. Не нажимать кнопки слияния GitHub. Не давать `ПЕРЕПЛАНИРУЙ` при живых захватах. Не писать токен в чат и в файлы. Не возобновлять брошенные чаты — запускай новых кодеров, они подхватят работу с последнего зелёного состояния.

### 0.8 Частые вопросы

**Я уже навертел исходники вручную — их выбросят?** Нет. Первый кодер обязан провести аудит и по умолчанию сохранить всё рабочее. Переписывание — только с доказательством поломки, удаление — только с доказательством, что код никем не используется. Все удаления происходят в ветке и обратимы через историю git.

**Подойдёт для любого моего репозитория?** Да. Стек един: Java 21, Maven, переносимый EXE через jpackage. Он применяется всюду, где создаётся программа. В чисто документном репозитории каркас не создаётся — там проверяются шапки md+ и ссылки.

**Нужен Windows-EXE.** Он собирается на раннере GitHub Actions `windows-latest`, потому что jpackage собирает Windows-пакет только на Windows. Готовый ZIP лежит в Releases и артефактах, в git не коммитится.

**Бот умер молча.** Ничего не потеряно: в ветке лежат только зелёные состояния. Аренда истечёт через 80 часов, либо ты дашь `ОСВОБОДИ` или `ПРОДОЛЖИ`.

**Сменилась модель.** Протокол от модели не зависит: всё состояние в файлах, а не в памяти чата.

**Что значит «версии пинованы».** Версии плагинов и actions прибиты к конкретным числам, чтобы сборка не ломалась сама собой. Поднимать — только рычагом `ОБНОВИ ВЕРСИИ`.

**Почему код не сжат в один символ.** Проверено: короткие ASCII-имя и удаление комментариев-пересказа уменьшают и символы, и токены. Односимвольные Unicode-имена уменьшают символы, но увеличивают токены и ломают кодировки. Приняты только те приёмы, где выигрыш двойной. Подробности в Части 13.

# ЧАСТЬ 2. ПЕРВЫЙ КОДЕР

**2.1. Захват роли первого.** Клонируй репозиторий. Если он пуст — создай начальный коммит в main. Создай локальную ветку от main, напиши в неё все файлы плана (2.2–2.4), закоммить и выполни:

**2.2. Аудит наследия.** Прочитай ТЗ. Составь опись всех исходников. Зафиксируй базовую линию: собирается ли проект, какие тесты падают. Каждому существующему файлу — вердикт в `GVK/AUDIT.md`:

| Вердикт | Когда | Доказательство |

| KEEP | соответствует ТЗ или не противоречит | по умолчанию, обоснование не требуется |

Сохраняй лучшее, убирай худшее, не переписывай по вкусу. Нет доказательства — KEEP. Удаления только в ветке фрагмента.

# ЧАСТЬ 3. ЗАХВАТ ФРАГМЕНТА

# ЧАСТЬ 13. СТИЛЬ И СЖАТИЕ КОДА

Цель: меньше символов **и** меньше токенов одновременно. Приняты только приёмы с двойным выигрышем.

**13.1. Принято.**

| Приём | Правило |
|---|---|
| Локальные имена | короткие ASCII: `i`, `n`, `k`, `s`, `p`, `tmp` |
| Публичные имена | осмысленные: классы, методы, поля — контракт из `PORTS.md`, переименование только через заявку |
| Комментарии | убрать пересказ кода; оставить одну строку смысла на класс и на нетривиальный метод; атрибуция обязательна |
| Дедупликация | повтор вынести в метод; мёртвый код удалить по вердикту DELETE |
| Служебные файлы | `GVK/*.md` — только таблицы и поля, без прозы |

Дедупликация даёт больший выигрыш, чем переименование. Начинать с неё.

**13.2. Запрещено.** Односимвольные не-ASCII идентификаторы: символов меньше, токенов больше, ломаются кодировки, усиливается дрейф сигнатур. Минификация исходников (склейка строк, удаление пробелов и переводов строк): Java компилируется, выигрыша в скорости и размере байткода нет, а разбор для бота ухудшается.

**13.3. Исключения.** Часть 0 протокола и README остаются полностью человекочитаемыми.

**13.4. Транспорт.** Длинные логи и простыни, передаваемые в чат, сжимать SaberW-2 (словарное сжатие CJK с обратимостью). Исходники в репозитории хранятся в обычном виде: сжатие применяется к передаче, не к хранению.

# ЧАСТЬ 15. ВЫКЛЮЧЕННЫЕ ПО УМОЛЧАНИЮ МЕХАНИЗМЫ

Оба механизма включаются только рычагом владельца. Без рычага не применять.

## 15.1. Контролёр (рычаг ПРОВЕРЬ NNN)

Роль проверки. Код не менять, только читать. Контролёр не может быть автором проверяемого фрагмента.

Проверить: соответствие ТЗ; границы пакета по `PLAN.md`; отсутствие функциональности сверх ТЗ; сходимость чисел в отчёте; реальное наличие файлов, о которых отчитались; атрибуцию; паритет EN/RU в затронутых разделах README; грамматику в README и комментариях.

Результат — `GVK/reviews/NNN.md`: вердикт ПРИНЯТО или ВЕРНУТЬ, список замечаний, хэш проверенного коммита. Повторная проверка того же хэша запрещена.

Обязателен для фрагмента 000 и для любого фрагмента, меняющего порт. Для остальных — по рычагу. Механические проверки уже автоматизированы в 4.9 и 7.9, дублировать их не нужно.

## 15.2. Гвк-э (рычаг ГВК-Э)

Словарное сжатие служебных полей. Формат словаря:

```
Словарь - начало.
Ы mvn -B -ntp verify → Failures: 0, Errors: 0
Э захват отозван, работу выбросить, отчёт, выход
Ю файл не читается, запись не состоялась
Словарь - конец.
```

Код — первое слово строки, значение — всё остальное до конца строки. Словарь хранится в `GVK/DICT.md`, пополняется только с разрешения владельца.

**Разрешено:** поле `remaining` в `reports/NNN.md`, поле `доказательство` в `AUDIT.md`, внутренние заметки бота.

**Запрещено:** исходный код, README, `PLAN.md`, `STATE.md`, отчёт в чат, сообщения коммитов и сам протокол. Правила обязаны быть однозначными.

**Правило выгоды:** заменять только длинные частые фразы. Короткие статусы не заменять: один CJK-символ стоит 2–3 токена, слово «ЗЕЛЕНО» — 2. Выигрыша нет.
