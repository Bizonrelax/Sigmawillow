# Принято

| № | Решение |
|---|---|
| 1 | Стек един для всех программных репозиториев: Java 21, Maven, переносимый EXE через jpackage app-image, Windows 11. Ассемблер — единственная альтернатива. БД запрещены, данные в файлах, перенос копированием папки |
| 2 | Приоритет стека протокола над стеком ТЗ; расхождение фиксируется в AUDIT.md |
| 3 | Атомарный захват: PUT contents без sha. 201 — моё, 422/409 — занято |
| 4 | Поколения (epoch) для отзыва фрагмента. Аренда 80 часов + продление при возобновлении |
| 5 | Один кодер = один фрагмент. Несколько — по рычагу СЕРИЯ |
| 6 | Красное не пушится никогда. Зелёные микро-чек-поинты пушатся сразу |
| 7 | Отчёт ≤30 строк, последние две строки СОСТОЯНИЕ и ВЕРДИКТ |
| 8 | Ожидание: опрос раз в 10 мин, потолок 2 часа, рычаг ЖДИ N |
| 9 | Слияние выполняет только закрывающий кодер, порядок из LINKS.md, чистый финиш |
| 10 | PLAN/PORTS/LINKS/AUDIT — неизменяемая ветка gvk-plan. claims/reports/STATE — main |
| 11 | README: сначала EN, затем RU, полный паритет, GFM, без YAML-шапки |
| 12 | Атрибуция: THIRD-PARTY-NOTICES.md + licenses/ + раздел Credits в конце обеих частей README (конвенция из SaberW) |
| 13 | Комментарии атрибуции неудаляемы — юридическое требование |
| 14 | Сжатие: служебные файлы только таблицами; локальные имена короткие ASCII; публичные имена осмысленные; комментарии-пересказ убрать, смысл оставить; дедупликация. SaberW-2 — только транспорт для чата |
| 15 | Токен только через переменную среды GH_TOKEN. В чат, файлы, .git/config, историю не попадает |
| 16 | Статичная документация — в поле «Описание» среды; протокол читает её оттуда, при отсутствии — из репозитория |
| 17 | Вопросы владельцу не задаются никогда. Неоднозначность решается правилом по умолчанию и записывается в AUDIT.md |

# Отклонено

| Что | Почему |
|---|---|
| TDMA, временные слоты | зависит от часов и дисциплины моделей; атомарный захват сильнее |
| Теги claim-NNN и тег gvk-state | засорение имён, дублирование STATE.md, лишний вызов |
| Ветки ради безопасности | ветка нужна только для изоляции фрагмента и отзыва поколения |
| Красные WIP-пуши | в ветке существуют только зелёные состояния |
| Протокол вложением в проект Qwen | отклонено владельцем |
| Односимвольные Unicode-идентификаторы | символов меньше, токенов больше; ломает кодировки, усиливает дрейф сигнатур |
| Launch4j | заменён jpackage |
| «Плана нет → запусти первого» | кодер сам объявляет себя первым |

# Исправлено

| № | Ошибка | Правка |
|---|---|---|
| П1 | Слияние через Git Data API уничтожило всю папку GVK (коммит 3e89efd9) | слияние только git merge или PUT /pulls/N/merge; создание коммита с чужим деревом запрещено |
| П2 | Успех записи не проверялся | после записи прочитать обратно; после слияния число файлов не должно уменьшиться |
| П3 | Термин fast-forward употреблён неверно | fast-forward = перенос указателя на существующий потомок, без новых деревьев |
| П4 | Отказ «чужие учётные данные» | заявление о владельце токена в протоколе; токен из GH_TOKEN |
| П5 | — | отклонено |
| П6 | Не задан адресат записи | писать только в репозиторий из селектора чата; Sigmawillow — только чтение |
| П7 | CI не запускался на ветках фрагментов | добавить gvk/** в триггер push |
| П8 | Слияние 000 не было разрешено | первый кодер сливает 000 в main сразу |
| П9 | Конфликт стека ТЗ и протокола | приоритет протокола |
| П10 | README EN/RU не совпадали | проверка паритета заголовков при закрытии |
| П11 | .gitignore: взаимно отменяющиеся строки | не смешивать шаблон с существующим файлом |
| П12 | Отчёт: последние две строки слиты | строго две отдельные строки |
| П13 | Атрибуция отсутствовала | раздел 12 протокола |
| П14 | Тест и код расходились, арбитр не задан | арбитр — ТЗ; решение в AUDIT.md |
| П15 | Кодер изменил чужой .gitignore | .gitignore, pom.xml, workflow — собственность фрагмента 000 |
| П16 | В изменения попали артефакты сборки | перед коммитом git status --porcelain содержит только файлы своего пакета |
| П17 | Токен оказался в рабочем дереве | grep на токен перед коммитом; найдено — стоп |
| П18 | Документация только из репозитория | два источника: описание среды, затем репозиторий |
