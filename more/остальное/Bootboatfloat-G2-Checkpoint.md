ЧАСТЬ E. СЕРВЕР 2 — МЕХАНИКИ
=====================================================================
E1. СНБ (свойства нулевых блоков), квадрат +-300 от 0;0 (600x600)
    Время добычи лучшим подходящим инструментом = 1 час
    Худший инструмент — дольше в той же пропорции, что в ванили
    Блок НЕ разрушается: выпадает копия блока, сам блок остаётся
    Руда выпадает БЛОКОМ РУДЫ, не материалом (даже алмазная/железная)
    Поставленный игроком СНБ: прочность растёт равномерно за час
      минимум = добыча за 1 минуту лучшим инструментом, максимум = 1 час
      не растёт, пока блок добывают
      прервал добычу -> прочность растёт дальше, прогресс добычи сброшен
    РЕАЛИЗАЦИЯ (иначе нельзя): клиент считает прочность сам, сервер её не меняет.
      Эмуляция: Mining Fatigue высокой ступени (клиент не может доломать)
      + серверный таймер по ванильной формуле + sendBlockDamage (трещины)
      + полоса прогресса в action bar. API sendBlockDamage в Paper есть.
    ОТКРЫТО: на сервере 1 зона +-1500 запрещает строить; если сохранить её
      и на сервере 2, СНБ внутри неё недостижим. Либо сжать защиту до +-300,
      либо СНБ декоративен.
    ПОСЛЕДСТВИЕ: СНБ = бесконечная ферма блоков (копия без разрушения).
      Алмазную руду можно вынести и сломать вне зоны -> алмазы бесконечны.

E2. Телепорт односторонний
    Рамка с углами: ширина 8, высота 15 -> 42 блока периметра
    Состав: 10 обсидиана + 32 алмазных блока, порядок любой
      (32 алмазных блока = 288 алмазов)
      ОТКРЫТО: в ТЗ было "алмазной руды" и "алмазные блоки" — выбрать одно
    Активация автоматическая при готовой рамке
    Текстура активных блоков: красные рёбра каждой грани (ресурспак)
    Активные блоки: сломать нельзя, добыть можно (1 час лучшей киркой,
      пропорция для прочих инструментов как в ванили)
      ОТКРЫТО: добыча = копия блока + деактивация рамки, блок остаётся?
    Питание: воронка, прижатая к любому блоку рамки, только булыжник
      1 булыжник = 1 ТЕЛ, 1 ТЕЛ = 1 метр, линейно
      ванильная воронка не отдаёт в не-инвентарь -> плагин сам высасывает
      булыжник из инвентаря воронки, примыкающей к рамке
      скорость воронки 2.5 предмета/с: 1 км = 6.7 мин, 10 км = 67 мин зарядки
    Табличка: любое число и ничего другого, не больше накопленных ТЕЛ
    Ломает табличку -> телепорт того, кто сломал, строго по вектору взгляда
      на указанное число метров, ТЕЛ списываются
    ОТКРЫТО: точка прибытия в толще камня = удушье. Разрешить (свобода)
      или сдвигать к ближайшему воздуху? Высота и граница мира — клампятся.

E3. Апгрейд сундуков
    Условие: сундук полностью заполнен древесиной (любой), ПОЛНЫМИ стеками
    Появляется кнопка апгрейда в GUI -> уровень +1, до бесконечности
    Ёмкость: уровень N = базовая x 100^(N-1), принцип стеков сохраняется
      (число стеков предыдущего уровня x100)
      int64 кончается на 10 уровне -> счётчики BigInteger
    Прочность как у активных блоков телепорта (1 час лучшей киркой)
    Сломать нельзя, добыть можно
    Добыча: всё содержимое выпадает ОДНОЙ древесиной (одна сущность-предмет)
      подошёл -> в инвентарь залетает максимум, остаток висит
      воронка снизу тянет по одному: 1 млн предметов = ~111 часов (2.5/с)
    Текстура: белая горизонтальная полоска, одинаковая на всех уровнях
    Отображение: таблица "вещь — общее количество", пагинация
      (ванильное окно максимум 54 слота, числа — в описании предмета)
    Хранение: файлы, без БД

E4. Текстуры
    Красные рёбра телепорта и белая полоска сундука — ТОЛЬКО серверный ресурспак.
    Новых блоков сервер добавить не может: используются неиспользуемые
    состояния существующих блоков + модели пака.
    Пункт "клиенты ничего не скачивают" на сервере 2 НЕ ДЕЙСТВУЕТ.

ЧАСТЬ F. ФИНАНСЫ G2
=====================================================================
F1. Что такое G2
    Отдельный целевой сбор на железо/хостинг второго сервера.
    В ledger отдельной строкой: type=invoice, purpose=server2.
    НЕ смешивается с ежемесячным M. Сейчас ЗАМОРОЖЕН, не собирается.
F2. Формула целевого сбора
    G2 = ceil5( (H2 x месяцы_предоплаты + разовые_расходы + резерв) / (1 - fee - tax) )
    Пример: H2=3000, 6 мес = 18000, прочее 2000
            -> 20000 / 0.91 = 21978.02 -> G2 = 21 980 ₽
F3. Ежемесячный сбор после запуска сервера 2
    M_t = ceil5( (H_t + S + Прочее_t) / (1 - fee - tax) )
    H2=3000, S=5000 -> 8000/0.91 = 8791.2 -> M = 8795 ₽/мес СО ВСЕХ
F4. ВАЖНО: M — ОБЩИЙ сбор со всех игроков за месяц, счёт на игрока = M/N.
    Доход НЕ растёт с числом игроков, платёж на игрока падает.
    M=6375 -> 76 500 ₽/год;  M=8795 -> 105 540 ₽/год;  M=60000 -> 720 000 ₽/год
    НПД warn 2 млн и cap 2,4 млн практически недостижимы:
    нужен M = 200 000 ₽/мес, то есть хостинг ~177 000 ₽/мес.
    Счётчик warn/cap остаётся формальностью. Риск снят.
F5. Динамический сбор
    Пересчёт 1-го числа, публикация до 7-го, счета с 7-го, задним числом не меняется
    Рост: уведомление за 7 дней, со следующего месяца
    Падение: сразу со следующего месяца, балансы не сгорают
    Пол: не ниже уже предоплаченных обязательств
    Возврат до закупки железа — почти полный минус комиссия (ст. 32 ЗоЗПП)
F6. Хостинг сервера 2
    4 ГБ за 800 ₽ не годится. Ориентир: 8-16 ГБ RAM, NVMe 200+ ГБ, РФ, безлимитный трафик.
    Высота 4064 и второй подземный мир кратно увеличивают генерацию и диск.

ЧАСТЬ H. ЧЕГО НЕ БУДЕТ (упор в движок, не в умения)
=====================================================================
H1. Бесконечная вертикаль — невозможна. Предел Java 4064 блока (-2032..+2031),
    ограничение из-за 12 бит на Y в системе освещения.
H2. 10^20 блоков вниз — невозможно, в 2.5x10^16 раз больше предела.
    Даже моды бесконечной высоты упираются в 32-битное число.
H3. Настоящая прочность "1 час" — невозможна: прочность считает клиент.
    Максимум в ванили — обсидиан (50), ломается топовой киркой за 1.5 с.
    Для часа нужна прочность ~121 000. Только эмуляция (E1).
H4. "Никаких ограничений" по горизонтали — граница +-29 999 984 и ёмкость диска.
H5. Новые блоки и GUI без ресурспака — невозможны.
H6. Бесконечная вертикаль через клиентский мод (CubicChunks/C2Chunk) —
    противоречит принципу "клиенты ванильные", не рассматривается.
