### LEVERS.md — РЫЧАГИ ВЛАДЕЛЬЦА

Грузится только при рычаге или «продолжай». Без рычага этот файл в контекст не попадает.

L1. Синтаксис и приоритет. Строка, начинающаяся с `РЫЧАГ:`, — приказ. Выполнить только его, ничего больше. Рычаг перекрывает развилку C7 и общий стоп C9, права роли — только в пределах S7. Рычаг исполняет роль из `lever_map` реестра (L11): она захватывает свой захват по `claim`, читает свой файл роли и работает в своих правах. Рычаг исполняется до захвата любой другой роли. Несколько рычагов в одном сообщении — исполнить по порядку, отчёт по каждому. Рычаг, требующий роль-одиночку, захватывает `GVK/roles/<ROLE>.md`; занят — отчёт «рычаг занят другим агентом», выход.

L2. Таблица. Колонка «роль» — исполнитель по `lever_map`: рычаг без роли и без её прав не исполняется, guard отклонит запись.

L3. `продолжай` — универсальное возобновление в том же чате.

Триггер: сообщение без `РЫЧАГ:`, содержащее продолжай, продолжим, дальше, далее, начинай, работай, делай дальше, continue, go, next или иной явный приказ продолжить. Прошлая роль значения не действует: работает после любой роли, включая терминаторов и наблюдателя.

Сначала окружение: если `/opt/env.sh` и `/opt/gvk/p/PROTOCOL.md` существуют — протокол не скачивать и не перечитывать, окружение не собирать: только `. /opt/env.sh` и `git fetch origin`. Чего-то нет — G2 и C3.

Фаза A — доделать своё. Есть твой живой захват (`claims/NNN.md`, `fixes/NNN.md`, `roles/<ROLE>.md` с твоим `owner`) или незакоммиченные правки твоего фрагмента → продолжай его. Незакоммиченное не откатывать. Сначала тесты, довести до зелёного, пуш, отчёт, снять захват. Роль не менять, новых фрагментов не брать.

Фаза B — новичок. Своего незавершённого нет → вход заново по G4 в том же чате: перечитать срез C6 из репозитория, выбрать роль по C7, зарегистрировать рождение. Терминаторы, TZFIX, WISH и OBSERVER всегда идут по фазе B.

Состояние всегда из репозитория. `FINAL.md` есть → отчёт «работа завершена, агентов больше не запускать». `STOP.md` есть → C9.

L4. `ВОССТАНОВИ <путь> ИЗ <хэш>`.

Пройти шлюз G2. `git fetch origin`, затем `git checkout <хэш> -- <путь>`. Удалить из восстановленного мёртвые захваты и устаревшие служебные файлы. `STOP.md` из восстановления не возвращать: остановку снимает только `СНИМИ СТОП`. Привести `STATE.md` в соответствие: выполненные — `готов`, остальные — `свободен`. Восстановлен план, а ветки `gvk-plan` нет → создать её на этом коммите. Проверить: путь читается в main, число файлов не уменьшилось. Один коммит, обычный push в main, без force-push и слияний, код не трогать. Отчёт: восстановленные файлы, что удалено, состояние `STATE.md`. Событие `restore` в журнал.

L5. `ПОТОЛОК` — регулировка защиты от циклов и аренды. Значения в `GVK/LIMITS.md`, зеркало в `PEP.json.limits`. Файла нет → умолчания `cycles_max: 2`, `attempts_max: 3`, `stopfix_max: 2`, `lease_h_default: 8`, `lease_renew_h: 4`, `wait_h: 2`. Запись потолков проходит guard с `--allow-limits`: без рычага потолки не меняются (C10).

| Форма | Действие |
| --- | --- |
| ПОТОЛОК | показать текущие значения, ничего не менять |
| ПОТОЛОК N | `cycles_max = N` — циклы «проверка → исправление» на фрагмент |
| ПОТОЛОК БЕЗ ПРЕДЕЛА / ПОТОЛОК ∞ | `cycles_max = unlimited` |
| ПОТОЛОК ПОПЫТОК N | `attempts_max = N` — сессии на фрагмент |
| ПОТОЛОК ПОПЫТОК БЕЗ ПРЕДЕЛА | `attempts_max = unlimited` |
| ПОТОЛОК СТОПОВ N | `stopfix_max = N` — автоматические правки ТЗ по стопу на этап |
| ПОТОЛОК АРЕНДЫ N | `lease_h_default = N` — часы аренды по умолчанию для новых захватов |

Порядок: прочитать с `sha`, записать PUT с `sha`, при 409 перечитать и повторить один раз, поля `set_by`, `set_at` (время GitHub), обратное чтение. Действие в обе стороны немедленно: потолок повышен → фрагменты, `blocked` только из-за него, возвращаются в `свободен`, счётчики не обнуляются; понижен → превысившие немедленно `blocked`. `unlimited` → в каждом отчёте по такому фрагменту строка «Защита от циклов отключена владельцем». Агент по своей инициативе потолки не меняет. Отчёт: было → стало, что разблокировано или заблокировано.

L6. `ДОСТУП` — временное снятие ограничений (S7).

Формат: `РЫЧАГ: ДОСТУП <ROLE|NNN> <glob> [ЧТЕНИЕ|ЗАПИСЬ] [НА N ЧАСОВ]`. Владелец подтверждает строкой `РЫЧАГ: ДОСТУП ПОДТВЕРЖДАЮ` в том же чате; без подтверждения права не расширяются.

1. Записать `GVK/ACCESS.md` атомарно в main: `grantee` (роль или фрагмент, обязательно), `glob`, `mode`, `granted_by: owner`, `confirmed: true`, `granted_at`, `expires_at` (по умолчанию +2 часа, максимум 24), `reason`, `scope_note`. Событие `access_grant`. Запись доступна только исполнителю рычага с `--owner-lever`: обычная роль `ACCESS.md` писать не может (`hard_deny`).
2. Guard читает `ACCESS.md` из `origin/main`, а не из рабочего каталога, и применяет грант только при всех условиях S7: совпал `grantee`, есть `granted_by: owner` и `confirmed: true`, `expires_at` в будущем по времени GitHub. Локально созданный или просроченный файл прав не даёт. Истёкшую запись любой агент удаляет до развилки (C7), событие `access_expire`.
3. `ДОСТУП` расширяет только `read`/`write` в целевом репозитории. Не расширяет: `merge_main`, жёсткие запреты S2, запись в Sigmawillow, право менять `permissions` в реестре, право отключить guard.
4. Рычаг `СНИМИ ДОСТУП` удаляет `ACCESS.md` немедленно. Все действия под расширенными правами помечаются в журнале `detail: access=<glob>`.
5. Отчёт при выдаче: кому, что, на какой срок, что остаётся запрещённым. Одной строкой, без нотаций.

L7. `СОРЕЛ [major|minor|patch]` — релиз, исполняет ROLE_CLOSER.

1. Условия как для закрытия, плюс зелёный комплаенс. Тип релиза не указан → определить по изменениям: несовместимые правки API — major, новая функциональность — minor, только исправления — patch.
2. Поднять версию в файле версии принятого стека (`stack.version_file`: `pom.xml`, `pyproject.toml`, `*.csproj`, `go.mod`, `Cargo.toml`, `package.json`, `CMakeLists.txt`), обновить `CHANGELOG.md` по фактам отчётов и `STAGES.md`. Файл версии каркаса меняется только здесь и по рычагу `ОБНОВИ ВЕРСИИ`.
3. Создать аннотированный тег `release/vX.Y.Z` и ветку `release/vX.Y.Z` от текущего main, запушить оба. Тег не переносить и не удалять: история релизов неприкосновенна.
4. Собрать артефакты через CI (`windows-latest`), приложить ZIP к релизу GitHub. В git артефакты не коммитить.
5. Создать `GVK/FINAL.md` с полем `mode: release` и `REPORT/FINAL.json` с `mode: release`, `work_continues: true`, версией и ссылкой на артефакт. Уборку по ROLE_CLOSER 10 в режиме релиза **не выполнять**: ветку `gvk-plan`, ветки незавершённых фрагментов и захваты не удалять. Иначе развилка C7.1 остановит рой навсегда — это была ошибка v5.1. При `ЗАКРОЙ` пишется `mode: close`, уборка выполняется, новых агентов не запускать.
6. Событие `release_tag`, отчёт по G6 с версией релиза и ссылкой на артефакт.

L7.1. `СТЕК` — без аргумента роль OBSERVER показывает `REPORT/stack.json`: язык, версия, упаковка, статус шести критериев ST1, блокеры. С аргументом (`СТЕК python`, `СТЕК java`, `СТЕК dotnet`) работу исполняет WISH по ST8: оценка объёма переделки, `CHANGE-NNN.md`, новая ревизия ТЗ, пересборка плана. Работающий код не переписывать без доказательства провала ST1; если стек меняется по желанию владельца — это его право, объём переделки показать в отчёте.

L8. Тестовые и аварийные рычаги. `ТЕСТ-ПЛАН`, `ТЕСТ`, `ПОЖАР`, `ЛИЦЕНЗИИ` вызывают соответствующие роли; их механика — в файлах ролей, здесь только вход. Рычаг с номером (`ТЕСТ T-004`) адресный, без номера — роль выбирает задачу сама по приоритету. `РОЛИ` ничего не меняет. `СНИМИ РОЛЬ` не отменяет работу агента: он снимает только запись захвата, живой агент обнаружит это при проверке перед пушем (W6).

L9. `ГВК-Э` / `СЛОВАРЬ ОБНОВИ` — словарное сжатие служебных полей. Полные правила — `ECONOMY.md` E3–E6, грузить по факту.

Словари трёхуровневые и лежат в протоколе: `GUIDEGVK/dict/GLOBAL.dict.md` (все роли), `GROUP-CODE|GROUP-TEST|GROUP-STATE.dict.md` (группы), `ROLE-<ROLE>.dict.md` (роль). Словарь проекта — `GVK/DICT.md`, ведёт FIRST по этому рычагу. Формат строки: код, пробел, фраза до конца строки. Код самоадресный: `%` + адрес словаря + номер (`%g3` — общий, `%k1` — группа кода, `%d2` — DEV, `%j5` — проект). Коллизии кодов запрещены, проверяет `dict.py load`.

```text
%g3 файл не читается, запись не состоялась, повторить или доложить
%k1 mvn -B -ntp verify → Failures: 0, Errors: 0
%d3 остаток работы: следующий шаг и имя падающего теста
```

Порядок рычага: `dict.py propose --corpus REPORT --corpus GVK --ns j` → кандидаты с измеренной выгодой → владелец или FIRST оставляет только выгодные → запись `GVK/DICT.md` → `dict.py audit` → событие `dict_update` → отчёт: было записей, стало, выгода в токенах. Запись короче 6 токенов или реже 3 повторов в словарь не берётся: сжатие не выигрывает.

Разрешено: `remaining`, `remarks`, `symptom`, `manual_notes`, `why`, `note`, `detail`, `proof` — служебные строковые поля, и блоки `<!--DICT:BEGIN-->…<!--DICT:END-->` в `AUDIT.md`. Запрещено: исходный код, README, `PLAN.md`, `STATE.md`, `STAGES.md`, `STOP.md`, ключи и enum JSON, пути, хэши, идентификаторы, сообщения коммитов, отчёт в чат, сам протокол. Словарь в контекст агента не грузится: сжимает и раскрывает инструмент (E4).

L10. Рычаги при стопе исполняются всегда. Запрещено: исполнять рычаг частично и «заодно» делать другую работу; менять ТЗ по рычагу, который этого не предполагает; отвечать на рычаг вопросом.

L11. Роль-исполнитель рычага. Каждый рычаг имеет ровно одного исполнителя в `lever_map` реестра. Порядок: определить роль по `lever_map` → захватить её `claim` (одиночка — `GVK/roles/<ROLE>.md`, `ОТОЗВАТЬ`/`ОСВОБОДИ`/`СНИМИ РОЛЬ` — TERMINATOR2) → прочитать файл роли и `needs` → выполнить только рычаг → отчёт и выход. Рычаг, для которого роль занята живой арендой, не исполняется: отчёт «рычаг занят другим агентом», выход. Рычаги без записи (`ПАМЯТКА`, `РОЛИ`, `СТЕК`, `РАСХОД`, `СЛОВАРЬ`, `ТОЛЬКО ОТЧЁТ`) исполняет OBSERVER без захвата. Исполнять рычаг «от себя», без роли и прав, запрещено: guard отклонит запись, а обход запрещён C10.15.
