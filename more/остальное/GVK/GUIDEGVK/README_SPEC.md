### README_SPEC.md — README.md

D1. Кто пишет. Первый кодер создаёт скелет из ТЗ. Каждый владелец фрагмента, меняющий видимое поведение, дописывает свой раздел. Закрывающий кодер приводит README в полное соответствие программе.

D2. Структура. Две части: сначала полностью английская, затем полностью русская. Русская — не сокращённый перевод, а полный эквивалент: те же разделы, те же примеры, тот же объём деталей.

Порядок: `# Имя программы` → строка навигации `[English](#english) | [Русский](#русский)` → `## English` → разделы EN → `---` → `## Русский` → те же разделы RU в том же порядке.

| Раздел | Содержимое |
| --- | --- |
| What it is / Что это | одно предложение без маркетинга |
| Who it is for / Для кого | конкретные роли и ситуации |
| Why / Зачем | какую проблему решает, чем лучше ручного способа |
| Features / Возможности | только то, что реально работает; планы помечать явно |
| Requirements / Требования | Windows 11 x64; среда исполнения внутри папки либо бесплатный шаг с инструкцией; ничего платного |
| Download / Скачать | ссылка на Releases, имя ZIP, что внутри |
| Installation / Установка | распаковать ZIP в любую папку, запуск без прав администратора и без интернета; если нужен бесплатный шаг — точная инструкция; перенос копированием папки; предупреждения SmartScreen и антивируса описать честно |
| Quick start / Быстрый старт | минимальный сценарий от запуска до результата, 5–7 шагов |
| User manual / Руководство пользователя | подробно: каждый пункт меню, каждое поле, каждая кнопка, каждый флаг, каждый формат ввода и вывода, с примерами |
| Examples / Примеры | реальные проверенные примеры вход → выход |
| Data storage / Хранение данных | какие файлы создаются, где, что можно переносить |
| Troubleshooting / Проблемы | таблица: симптом → причина → решение |
| FAQ / Вопросы | не менее 5 реальных вопросов |
| Limitations / Ограничения | чего программа не делает |
| Uninstall / Удаление | удалить папку |
| License / Лицензия | из файла LICENSE; не выдумывать |
| Credits / Заимствования | LICENSES.md, в самом конце каждой языковой части |

D3. Разметка. Только GFM, из HTML разрешены `details` и `summary`. YAML-шапки в README нет. Один `#` на файл, уровни не перескакивать. Пустая строка до и после списков, таблиц, блоков кода. У каждого блока кода указан язык после трёх обратных кавычек. В таблицах строка-разделитель обязательна, вертикальную черту внутри ячейки экранировать обратным слэшем. Ссылки на файлы — относительные, на скачивание — на Releases. Скриншоты только реально созданные. Никаких «и т.д.» в руководстве: либо описано, либо в «Ограничения».

D4. Проверка при закрытии. Состав разделов EN и RU одинаков (сверить заголовки). Каждая описанная команда и каждый пример проверены: логика и CLI — на Linux, Windows-шаги — по артефакту CI с честной пометкой «вручную не проверено». Все ссылки существуют. Расхождение README с поведением = красное, ТЗ не закрывать.

D5. README — лицо проекта, он остаётся полностью человекочитаемым. Правила сжатия C11 к нему не применяются.
