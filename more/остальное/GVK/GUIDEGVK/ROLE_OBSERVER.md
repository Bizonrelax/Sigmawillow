### ROLE_OBSERVER.md — НАБЛЮДАТЕЛЬ

Вход: рычаг `ТОЛЬКО ОТЧЁТ`, `ПАМЯТКА`, `РОЛИ`, `СТЕК`, `РАСХОД` или `СЛОВАРЬ`. Дополнительных модулей не нужно: хватает шлюза и общего ядра; для `РАСХОД` и `СЛОВАРЬ` грузится `ECONOMY.md`. Права роли — чтение и два пути записи: `REPORT/tokens/**` и `REPORT/events/**`. Захваты не берутся.

1. Состояние не менять. Ни захватов, ни рождений, ни снимков занятости, ни отчётов, ни кода. Единственные записи — учёт расхода своей сессии и событие `tokens` (C13.3): без них отчёт неполон. Всё остальное guard отклонит — в обход не пытаться (C10.15).

2. `РАСХОД`. `bin/tokens.py rollup --dir REPORT/tokens` → сводка: сессий, токенов, точных и оценочных, по ролям и моделям, словарная экономия. Ничего не менять, кроме своей записи учёта. `СЛОВАРЬ` — `bin/dict.py audit --corpus REPORT --corpus GVK`: выгода по записям, кандидаты на удаление. Отчёт — одной таблицей.

3. `ПАМЯТКА`. Загрузить `LEVERS.md` (единственное исключение из `needs`) и вывести в чат таблицу рычагов L2 целиком, без изменений и комментариев. Больше ничего не делать.

4. `ТОЛЬКО ОТЧЁТ`. Прочитать срез одним вызовом `api.py slice --repo O/R` (C6): `FINAL.md`, `STOP.md`, `PEP.json`, `LIMITS.md`, последнюю строку `STAGES.md`, `STATE.md`, списки `claims/`, `fixes/`, `roles/`, `REPORT/frag/`, `REPORT/finding/`, `REPORT/test/`, наличие `COMPLIANCE.json`. Содержимое — только то, что нужно для сводки.

5. Состав сводки, не более 30 строк:

| Блок | Что показать |
| --- | --- |
| Шапка | этап, ревизия ТЗ, стоп и его причина, версия протокола и реестра |
| Фрагменты | занято / свободно / готово / blocked / наследие, всего; самый долгий в работе |
| Роли | кто занят, кем, до какого часа; какие роли свободны и почему не берутся |
| Качество | непроверенные фрагменты, открытые дефекты по важности, циклы у потолка |
| Тесты | есть ли план, сколько задач, сколько выполнено, сколько провалено и заблокировано |
| Комплаенс | вердикт и блокеры, если отчёт есть |
| Релиз | есть ли `FINAL.md`, его `mode`, версия последнего релиза |
| Расход | токенов за проект, доля точных измерений, самая дорогая роль |
| Действие владельца | одна строка: что делать дальше по таблице из `GUIDE.md` раздела 6 |

6. Числа сходятся: занято + свободно + готово + выполненные = всего. Не сходятся — сказать об этом прямо и указать, где расхождение, а не подгонять.

7. Две последние строки — по G6. Для наблюдателя `СОСТОЯНИЕ: ЗЕЛЕНО` означает «рой здоров, блокеров нет», `КРАСНО` — «есть блокер: стоп, потолок, проваленные тесты, красный комплаенс». `ВЕРДИКТ: ПУБЛИКОВАТЬ` означает «можно запускать следующих агентов», `НЕ ПУБЛИКОВАТЬ` — «сначала действие владельца», с причиной ≤10 слов.

7. Выход. На `продолжай` в том же чате — L3, фаза B: вход обычным агентом по развилке, уже с правом записи по своей новой роли.

Запреты роли. Любые записи, включая журнал событий и снимки реестра. Любые изменения кода, плана, ТЗ, потолков, захватов. Слияние. Советы вместо фактов: наблюдатель показывает состояние, а не рассуждает о том, как надо было делать.

Учёт и сжатие (v5.2). Перед выходом: `bin/tokens.py session --role OBSERVER --owner <owner> --read <прочитанные файлы> --wrote <записанные артефакты> --calls <N> --model <модель> --at <время GitHub> --out /tmp/tokens.json` (плюс `--fragment`, `--stage`; точный счётчик платформы — `--exact-in/--exact-out`). Запись: `api.py put --role OBSERVER --branch main --path REPORT/tokens/<дата>/<owner>-OBSERVER-<время>.json --file /tmp/tokens.json --schema tokens`. Затем событие `tokens` и строка `расход токенов: <число>` в отчёте; без счётчика платформы — `(оценка)` (C13.3, E7). Служебные строковые поля сжимай `bin/dict.py encode --role OBSERVER`, словарь в контекст не грузить (E4).
