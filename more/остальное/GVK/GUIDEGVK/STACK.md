### STACK.md — СТЕК И ПЕРЕНОСИМОСТЬ

Грузится FIRST (выбор стека) и CLOSER (приёмка поставки); остальным — по факту работы с упаковкой, наследием или сменой стека. Отменяет прежнюю догму «стек протокола выше стека ТЗ»: язык не навязывается. Шаблоны каркаса своего стека — SKEL_JAVA.md, SKEL_PY.md, SKEL_OTHER.md; чужие не грузить.

ST1. Критерий результата — единственное, что протокол требует жёстко. Поставка обязана удовлетворять всем шести пунктам:

| № | Критерий | Чем доказывается |
| --- | --- | --- |
| 1 | Работает на Windows 11 x64 | прогон на раннере `windows-latest`, артефакт запуска |
| 2 | Запуск без прав администратора и без обязательной установки | запуск из распакованной папки под обычным пользователем |
| 3 | Среда исполнения внутри поставки либо бесплатна и свободно распространяема | состав поставки, лицензии компонентов, `runtime_cost: none` |
| 4 | Установка и первый запуск офлайн | прогон без сети; сетевые функции — только если их требует ТЗ |
| 5 | Перенос копированием папки, данные в файлах | копирование в другой путь с пробелами и кириллицей, повторный запуск |
| 6 | Инструкции по установке, переносу и удалению в README EN и RU | разделы Requirements, Installation, Uninstall с честными оговорками |

Никаких доплат: платные рантаймы, подписки, лицензии на пользователя, виртуальные машины, облачные сервисы, коммерческие СУБД и обязательные внешние серверы — запрещены. «Почти под ключ» допустимо только как бесплатный шаг с инструкцией (распаковать ZIP, разрешить запуск в SmartScreen), но не как покупка.

ST2. Порядок выбора стека, первое подходящее обязательно: (1) прямое требование ТЗ к языку, библиотеке или формату — ТЗ требует Python, значит Python; (2) работающий код и наследие репозитория — проект на Python продолжать на Python; (3) выбор агента под задачу и ST1, если ТЗ и наследие молчат: математика — Python (numpy/scipy), настольный GUI — PySide6, tkinter или Java/Swing, системные утилиты — Go, Rust, C++.

Решение фиксируется в `GVK/AUDIT.md` и `REPORT/stack.json`: язык, версия, упаковка, лицензии, чем закрыт каждый пункт ST1. Прежние запреты протокола на язык отменены; ссылка на них как на основание отказа — нарушение ST3.

ST3. Запрет отказа по расширению файла. Агент не вправе отказываться от `*.py`, `*.ipynb`, `*.go`, `*.rs`, `*.cs`, `*.js`, `*.cpp` и любых других исходников только потому, что язык не Java. Отказ допустим лишь по провалу ST1 и лишь с доказательством: компонент требует платы, не переносится на Windows 11 или требует обязательного сервера. Доказательство — лицензия, вывод команды или трассировка, а не ссылка на протокол. «Протокол требует Java» не является основанием ни для отказа, ни для переписывания.

ST4. Допустимые стеки: Python 3.11–3.12 (CPython с python.org), Java 21 (Temurin, Liberica), .NET 8+, Go, Rust, Node.js, C/C++ — все бесплатны и упаковываются в самодостаточную поставку. Команды сборки и ловушки стоимости своего стека — в его файле каркаса; знать заранее: Anaconda `defaults` платна для организаций свыше 200 человек, PyQt в закрытом продукте платен (брать PySide6 или tkinter), Oracle JDK NFTC не брать по умолчанию. Смешанный стек допустим, если поставка целиком проходит ST1; компоненты аудирует COMPLIANCE по LICENSES.md.

ST5. Математика и наука: Python предпочтителен, отказ от `.py` здесь — дефект. Обязательны пины `==`, фиксированный `seed`, численные тесты, явные `hiddenimports` при упаковке (SKEL_PY.md).

ST6. Проверка переносимости. Выполняется на `windows-latest`, факты пишутся в `REPORT/stack.json`:

собрать поставку в CI и выложить ZIP; распаковать в путь с пробелами и кириллицей (`C:\Проверка GVK\app`); запустить под обычным пользователем без сети; скопировать папку во второй путь и запустить снова (данные и настройки переживают копирование); удалить папку без деинсталляции; зафиксировать размер поставки, наличие рантайма внутри, требования к пользователю, предупреждения SmartScreen и антивируса.

Приложение обязано поддерживать `--selftest`: прогон логики без GUI, код возврата 0 — проверка автоматическая. Провал любого пункта — красное: поставка не принимается, задача уходит в план. Локально проверяется только логика и тесты; переносимость доказывается артефактом CI, а не рассуждением.

ST7. Каркас и пины. Каркас — по стеку (SKELETON.md K1 плюс файл своего стека). Версии инструментов, зависимостей и actions прибиты к числам, поднимать только рычагом `ОБНОВИ ВЕРСИИ`. Файлы каркаса принадлежат фрагменту 000 и защищены guard-ом через `@skeleton`.

ST8. Смена стека посреди проекта. Только по рычагу `СТЕК <стек>` или `ЖЕЛАНИЕ`, исполняет WISH: оценка выполнимости, `CHANGE-NNN.md`, новая ревизия ТЗ, пересборка плана и оценок. Выполненное и зелёное не выбрасывать без доказательства провала ST1. Переписывание работающего кода на другой язык «для единообразия» запрещено: трата квоты без выигрыша. Если причина — провал переносимости, доказательство обязательно и попадает в `CHANGE`. Технически смену `stack` в реестре guard пропускает только с `--allow-stack` (рычаг `СТЕК`/`ЖЕЛАНИЕ`); FIRST правит стек без рычага лишь при инициализации.

ST9. Машинный след. `REPORT/stack.json` по схеме `stack`: `language, version, packaging, runtime_included, runtime_cost` (только `none` или `free-step`), `licenses[]`, `checklist[]` (шесть пунктов ST1: критерий → факт → статус), `blockers[]`, `decided_by`, `tz_ref`, `at`, `owner`; файл версии стека — `stack.version_file` реестра. Пишет FIRST при выборе, обновляет DEV при упаковке, проверяет CLOSER при приёмке. Валидация до записи обязательна (C12.4); чек-лист короче шести пунктов или платная среда не проходят валидацию.

ST10. Что не изменилось: зелёные чек-поинты, границы владения и guard, пины, атрибуция, README EN/RU, привязка к ревизии ТЗ, защита от циклов, порядок слияния, релиз по `СОРЕЛ`. Свобода языка не отменяет ни одного правила.

ST11. Хранилище данных. Запрещены серверные и платные СУБД, требующие установки, службы или лицензии. Встраиваемое хранилище в файлах — обычные файлы, SQLite, встроенные key-value — разрешено и переносится копированием папки. Критерий тот же: ST1, пункты 2–5.

ST12. Документный репозиторий. Если по C5 репозиторий документный (`repo_kind: doc` в реестре), каркас не создаётся, ST1 и ST6 не применяются, `REPORT/stack.json` не требуется. Критерии готовности: валидные шапки md+, существующие относительные ссылки, непротиворечивость документов. Тест-план не требуется, комплаенс обязателен. Приёмка — Q7 для `doc`.
