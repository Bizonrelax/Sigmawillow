### SKELETON.md — КАРКАС ПРОЕКТА (ФРАГМЕНТ 000)


K1. Маркеры каркаса и файлы, принадлежащие фрагменту 000, берутся из `stack.skeleton_by_stack[язык]` реестра (карточка роли), а не из привычки: для python это `pyproject.toml`/`requirements.txt`, для java — `pom.xml`/`build.gradle`, для .NET — `*.csproj`, для go — `go.mod`, для rust — `Cargo.toml`, для node — `package.json`, для C/C++ — `CMakeLists.txt`. Каркас создаётся по стеку, выбранному по STACK.md ST2: требование ТЗ, затем наследие, затем выбор агента под критерии ST1. Язык протоколом не навязывается. Тип репозитория — C5.

| Стек | Файл каркаса | Разделы | Команда готовности |
| --- | --- | --- | --- |
| java | SKEL_JAVA.md | K2, K4, K5 | `mvn -B -ntp verify` → Failures: 0, Errors: 0 |
| python | SKEL_PY.md | K6, K7 | `python -m pytest -q` → все пройдены |
| .NET, Go, Rust, Node, C/C++ | SKEL_OTHER.md | K8 | по таблице K8 |

Загрузи файл своего стека, чужие не грузи. Существующие файлы каркаса не перезаписывать вслепую: сверить с шаблоном, дописать отсутствующее, расхождения зафиксировать в `GVK/AUDIT.md`. Файлы каркаса любого стека принадлежат фрагменту 000 и защищены guard-ом (`@skeleton`).

K9. Приёмка каркаса. Локально — команда готовности стека с нулём падений. В CI — сборка поставки и проверка переносимости. Красный CI означает, что фрагмент 000 не завершён. Результат проверки переносимости пишется в `REPORT/stack.json` (ST9), а не в текст отчёта «должно работать».
