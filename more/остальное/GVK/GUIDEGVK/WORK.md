### WORK.md — РАБОЧИЙ ЦИКЛ КОДЕРА

Грузится только ролями, пишущими код: DEV, CLEANER, FIRST (фрагмент 000), CLOSER (интеграция), FIREFIGHTER (уборка). Остальным не нужен.

W1. Старт. Прочитай `REPORT/frag/NNN.json` (или `GVK/reports/NNN.md` по F5, если репозиторий на v4.3): что сделано, где остановился, что не проверено. Начни с последнего зелёного коммита ветки, а не с нуля. Проверь `REPORT/ckpt/NNN.json`.

W2. Наследие обрабатывай по вердиктам `GVK/AUDIT.md`: KEEP, REFACTOR, REWRITE, DELETE. Сначала зелёный baseline, потом новое. Нет доказательства — KEEP.

W3. Микро-шаги и чек-поинты. После каждой правки — проверка сборки своего стека: java — компиляция, python — импорт модуля и `python -m compileall -q`, прочие — по K8. После шага — точечный тест. Полный набор — на чек-поинте. Зелёный чек-поинт → коммит и пуш немедленно, плюс обновить `REPORT/ckpt/NNN.json`: `fragment, last_green, step, tests, at`. Если у роли `lease_renew: true`, на каждом зелёном чек-поинте продлевай свою аренду на `limits.lease_renew_h` (по умолчанию 4 ч): живая работа держит фрагмент, мёртвый агент освобождает его за часы, а не за трое суток. Коммит — страховка, а не финал. В ветке существуют только зелёные состояния. Красное не пушить никогда. Откладывать пуш зелёного «до стабилизации окружения» запрещено (W13).

W4. Красное после микро-фикса → трассировка с печатью стадии, вывод в отчёт. Архитектуру без трассировочного доказательства не менять. Для бага сначала падающий регрессионный тест, потом лечение.

W5. Арбитр при расхождении теста и кода — ТЗ той ревизии, что зафиксирована в твоём захвате (`tz_sha`, C8.3). Не твоё ожидание, не текущее поведение и не более новая редакция ТЗ. Тест противоречит ТЗ → исправить тест. Код противоречит ТЗ → исправить код. Решение — в `AUDIT.md`.

W6. Проверка перед каждым пушем:

```bash
git fetch origin main
git show origin/main:GVK/claims/NNN.md
git show origin/main:GVK/STOP.md
git show origin/main:GVK/ACCESS.md
```

`epoch` не совпадает или захвата нет → захват отозван, работу выбросить, отчёт, выход. `STOP.md` появился → немедленно C9.3, отчёт, выход (исключение: стоп поставил ты сам и держишь `stopfix.md` или барьер терминатора). `ACCESS.md` истёк → права вернулись к обычным, действие вне прав не выполнять.

W7. Границы владения. Трогай только файлы своих пакетов или модулей и свои документы. Файлы каркаса своего стека (`.gitignore`, `pom.xml`, `pyproject.toml`, `requirements.txt`, `*.csproj`, `go.mod`, `Cargo.toml`, `.github/workflows/*`) принадлежат фрагменту 000 — менять нельзя, нужна заявка в `REQUESTS.md`. Чужой порт менять нельзя — заявка туда же. `PLAN.md` и ТЗ не менять (C10.13). Исключения: CLEANER правит пакет своего fix-захвата, CLOSER на время закрытия правит любые пакеты. Проверка границ программная — S3, а не «на глаз».

W8. Проверка перед коммитом:

```bash
. /opt/env.sh
python3 /opt/gvk/p/GUIDEGVK/bin/guard.py --role "$ROLE" --pep GVK/PEP.json \
  --branch "$BRANCH" --claim "GVK/claims/NNN.md" --staged
git status --porcelain
```

Guard проверяет пути, владение пакетом, ветку и секреты в диффе (включая буквальный токен владельца). Код возврата не 0 → коммит запрещён: убрать лишнее из индекса, записать событие `deny`, доложить. `git status` должен содержать только свои файлы. Артефакты сборки (`target/`, `dist/`, `*.lst`, `surefire-reports`, `*.class`, `*.jar`, `__pycache__/`), `env.sh`, файлы с токеном — недопустимы. Отдельный `grep` по диффу не нужен: он ловил только два префикса и пропускал остальное.

W9. Фрагмент с `ci: windows` проверяй через GitHub Actions на `windows-latest`. Локально Windows-поставку не собирать: и jpackage, и PyInstaller собирают Windows-пакет только на Windows. Проверка переносимости ST6 обязательна для фрагмента, меняющего упаковку или зависимости; результат — в `REPORT/stack.json`. Красный CI = фрагмент не завершён. GUI-проверки, невозможные в Linux-песочнице, уходят в CI и в задачи TESTER, а не в «предположительно работает».

W10. Меняешь видимое пользователю поведение — обнови соответствующий раздел README в обеих языковых частях в том же коммите (README_SPEC.md). Взял чужой код — в том же коммите запись в `THIRD-PARTY-NOTICES.md` и комментарий атрибуции над блоком (LICENSES.md).

W11. Конец квоты. Осталось около 3 вызовов до лимита → зафиксировать зелёное, записать учёт расхода (C13.3) и отчёт со статусом КРАСНО и точной точкой остановки: имя падающего теста, список изменённых файлов, следующий шаг. Захват не снимать, если работа не завершена — аренда удержит фрагмент. Отчёт и выход. Нехватка квоты не является основанием для общего стопа.

W12. Зависимости. Нужен чужой пакет, которого нет в main → подтяни ветку владельца в свою ветку:

```bash
git merge origin/gvk/OWNER
```

Порядок владельцев — из `LINKS.md`, включая ветки прошлых этапов. В main не сливать: интеграция происходит внутри твоей ветки, C10.6 не нарушается.

W13. Противоречивое окружение. Симптомы: файлы меняются без твоих правок, результаты тестов противоречивы в рамках одной сборки. Порядок, не более двух повторов:

1. Зафиксировать факты: пути, хэши до и после, команда, вывод.
2. Создать свежий клон в новый уникальный каталог (C4) и повторить ту же команду там.
3. Воспроизвелось → обычный дефект по W4: трассировка, падающий регрессионный тест, лечение.
4. Не воспроизвелось → работать в новом каталоге дальше; в отчёте одна строка «среда: повтор в чистом клоне, результат …».

Запрещено: гипотезы о параллельных процессах и мутации workspace, формулировки «аномалии среды», «ожидание стабилизации», откладывание пуша зелёного, просьбы к владельцу починить среду. Противоречие сохраняется после двух чистых клонов → КРАСНО с трассировкой; если оно делает требование ТЗ невыполнимым — W14.

W14. Невыполнимость ТЗ. Доказанная техническая невозможность требования (платформа, лицензия, внутреннее противоречие ТЗ) → C9.4: общий стоп с доказательством и `suggestion`. Не путать с нехваткой квоты (W11), красным тестом (W4) и сложностью задачи.

W15. Завершение фрагмента.

1. Пуш зелёного в `gvk/NNN`.
2. Валидировать отчёт по схеме `report` (C12.4) и записать `REPORT/frag/NNN.json`: статус, ветка, `last_green`, числа тестов, `stage`, `tz_sha`, `remaining`.
3. Обновить `GVK/STATE.md` (одна попытка, 409 → пропустить), обновить `REPORT/ckpt/NNN.json`.
4. Удалить свой захват `GVK/claims/NNN.md` (или `fixes/NNN.md`), снять снимок занятости в PEP.
5. Проверить записи обратным чтением (C12.5), дописать события (S5).
6. Записать учёт расхода: `bin/tokens.py session …` → `REPORT/tokens/<дата>/<owner>-<ROLE>-<время>.json`, событие `tokens` (C13.3, E7).
7. Отчёт по G6 и C13 со строкой `расход токенов: <число>`. Слияние в main не выполнять: ветка ждёт CLOSER (исключение — каркас 000 у FIRST).

W16. Рычаг `СЕРИЯ` и квота позволяет → вернуться к выбору следующего фрагмента. Без `СЕРИЯ` брать больше одного фрагмента запрещено (C10.9).

#### W17. Стиль и сжатие (алиас C11)

Цель: меньше символов и меньше токенов одновременно. Приняты только приёмы с двойным выигрышем.

| Приём | Правило |
| --- | --- |
| Локальные имена | короткие ASCII: i, n, k, s, p, tmp |
| Публичные имена | осмысленные: контракт из `PORTS.md`, переименование только через заявку |
| Комментарии | убрать пересказ кода; одна строка смысла на класс и на нетривиальный метод; атрибуция обязательна |
| Дедупликация | повтор вынести в метод; мёртвый код удалить по вердикту DELETE |
| Служебные файлы | `GVK/*.md` — таблицы и поля; `REPORT/*.json` — только поля контракта, без прозы |

Дедупликация даёт больший выигрыш, чем переименование: начинать с неё. Запрещено: односимвольные не-ASCII идентификаторы (токенов больше, кодировки ломаются), минификация исходников. Исключения: `GUIDE.md` и `README.md` остаются полностью человекочитаемыми. Транспорт: длинные логи в чат сжимать (хвост ≤ 20 строк); исходники в репозитории хранятся в обычном виде. Служебные строковые поля (`remaining`, `remarks`, `symptom`, `note`, `detail`, `proof`) сжимаются словарём через `bin/dict.py` — словарь в контекст не грузится (E4). Фрагмент `blocked` помечается в отчёте фрагмента полями `blocked/blocked_reason/block_kind`, а не правкой плана (C7.4).
