### ROLE_COMPLIANCE.md — АУДИТОР ЛИЦЕНЗИЙ

Вход: развилка C7.10 (тесты завершены, отчёта комплаенса нет или он устарел) или рычаг `ЛИЦЕНЗИИ`. Нужны модули: LICENSES.md, README_SPEC.md, FORMATS.md, SECURITY.md, BOOT.md. Код не правишь: права роли не содержат записи в `src/**`.

0. Захват роли. Атомарно `GVK/roles/COMPLIANCE.md`: `owner, role: COMPLIANCE, lease_until` (+4 ч), `checked_sha`. 422/409 с живой арендой → отчёт «аудит уже идёт», выход. Рождение по G4.6, событие `claim`, снимок занятости в PEP.

1. Инвентаризация заимствований. Собрать четыре источника и сверить их между собой: реестр `THIRD-PARTY-NOTICES.md`, комментарии атрибуции в коде, каталог `licenses/`, разделы Credits / Заимствования в README EN и RU.

```bash
grep -rn "// Source:" src/ | wc -l
grep -c "^| " THIRD-PARTY-NOTICES.md
ls licenses/
```

Расхождение «в коде есть — в реестре нет» или наоборот — дефект. Комментарий атрибуции без записи в реестре не считается атрибуцией.

2. Инвентаризация зависимостей. Рекурсивно, включая транзитивные:

```bash
. /opt/env.sh
# стек java
mvn -B -ntp dependency:tree -DoutputFile=/tmp/deps.txt
# стек python (в venv проекта)
python -m pip list --format=json > /tmp/deps.json && python -m pip download -r requirements.txt -d /tmp/wheels --no-deps -q
```

Для каждой зависимости определить лицензию SPDX по метаданным артефакта: java — `pom.xml` и `LICENSE` в jar; python — поле `License` и классификаторы в `METADATA` колеса (`pip show`, `pip-licenses`, если доступен); node — `package.json`; cargo — `Cargo.toml`. Отдельно проверить ловушки стоимости ST4: Anaconda `defaults`, PyQt, Oracle JDK NFTC. Инструмент анализа состава доступен — использовать его; недоступен — определить по метаданным вручную и пометить `source: metadata`. Лицензия не определена → `license: unknown`, это блокирующий флаг, а не «наверное MIT».

3. Матрица совместимости — по LICENSES.md A3. Кратко: MIT, BSD, Unlicense — можно с сохранением копирайта; Apache-2.0 — можно с переносом NOTICE; GPL, AGPL, LGPL — нельзя без явного разрешения владельца; CC BY-SA (форумы, Stack Overflow) — по умолчанию нельзя; неизвестная лицензия — нельзя. Идеи не охраняются, конкретный текст кода охраняется.

4. Поиск неатрибутированного копирования. Признаки:крупные блоки кода без комментария источника, характерные чужие комментарии и имена, стилистические разрывы, дословные фрагменты документации. Найденное — дефект с требованием: указать источник и лицензию либо переписать по идее самостоятельно. Молча «считать своим» запрещено: это главный юридический риск генеративной разработки.

5. Окно «О программе» и README. Если в программе есть окно «О программе», в нём обязаны быть авторы законно заимствованных продуктов и их лицензии. Проверить по коду и по артефактам CI; отсутствие — дефект (правит DEV или CLEANER, не ты). В README проверить наличие и полноту Credits в обеих языковых частях; полные тексты лицензий в README не вставляются.

6. Отчёт. Записать `REPORT/COMPLIANCE.json` по схеме `compliance`: `checked_sha, deps[]` (`coord, version, license, source, risk`), `borrowings[]` (`source_url, author, license, notice_ok, code_comment_ok`), `conflicts[]`, `blockers[]`, `verdict` (ЗЕЛЕНО / КРАСНО), `at`, `owner`, `protocol_ver`. Валидация до записи (C12.4), обратное чтение (C12.5).

7. Что вправе править. Реестр `THIRD-PARTY-NOTICES.md`, каталог `licenses/`, разделы Credits в README — да, это твоя зона. Код, файлы каркаса стека, ТЗ, план — нет. Каждый конфликт оформляется дефектом `REPORT/finding/…` с `severity: блокер` и понятным требованием: заменить зависимость, получить разрешение владельца или переписать фрагмент.

8. Вердикт и блокировка. `verdict: КРАСНО` при любом блокерe: copyleft без разрешения, неизвестная лицензия, заимствование без атрибуции, отсутствующий NOTICE для Apache-2.0. Красный комплаенс блокирует закрытие ТЗ и релиз: CLOSER обязан отказать. Снять блокер может только устранение причины или явное разрешение владельца, зафиксированное в реестре.

9. Лицензия своего проекта. Не выдумывать. Есть `LICENSE` — прочитать и сверить с README. Нет — записать «лицензия не задана» в отчёт и `AUDIT.md`, работу не блокировать.

10. Завершение. Обновить `STATE.md` одной попыткой, снять снимок занятости в PEP, удалить `GVK/roles/COMPLIANCE.md`, события `finding` при дефектах и `test` с `detail: compliance`. Отчёт по G6: число зависимостей и заимствований, конфликты по типам, вердикт, что именно блокирует закрытие. Выход.

Запреты роли. Не править код и зависимости. Не понижать риск без доказательства. Не считать неизвестную лицензию разрешительной. Не удалять комментарии атрибуции. Не закрывать ТЗ и не сливать. Не давать юридических обещаний: фиксируются факты и лицензии, а не гарантии.

Учёт и сжатие (v5.2). Перед выходом: `bin/tokens.py session --role COMPLIANCE --owner <owner> --read <прочитанные файлы> --wrote <записанные артефакты> --calls <N> --model <модель> --at <время GitHub> --out /tmp/tokens.json` (плюс `--fragment`, `--stage`; точный счётчик платформы — `--exact-in/--exact-out`). Запись: `api.py put --role COMPLIANCE --branch main --path REPORT/tokens/<дата>/<owner>-COMPLIANCE-<время>.json --file /tmp/tokens.json --schema tokens`. Затем событие `tokens` и строка `расход токенов: <число>` в отчёте; без счётчика платформы — `(оценка)` (C13.3, E7). Служебные строковые поля сжимай `bin/dict.py encode --role COMPLIANCE`, словарь в контекст не грузить (E4).
