### SKEL_OTHER.md — КАРКАС СТЕКА ПРОЧИЕ СТЕКИ

Грузится вместе с SKELETON.md только тем, чей стек — прочие стеки. Общие правила каркаса и приёмка — SKELETON.md K1, K3, K9; критерии поставки — STACK.md ST1.

K8. Прочие стеки: команды сборки, готовности и упаковки.

| Стек | Готовность | Поставка под Windows 11 |
| --- | --- | --- |
| .NET | `dotnet test` | `dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true` |
| Go | `go test ./...` | `GOOS=windows GOARCH=amd64 go build -o app.exe ./cmd/app` |
| Rust | `cargo test` | `cargo build --release --target x86_64-pc-windows-msvc` |
| Node.js | `npm test` | Node SEA или `pkg`, зависимости и рантайм в поставке |
| C / C++ | `ctest` или свой тестовый раннер | MSVC/MinGW со статическим рантаймом |

Для каждого стека CI обязан содержать job на `windows-latest`, который собирает поставку и прогоняет проверку ST6 (распаковка в путь с пробелами и кириллицей, запуск без сети и без прав администратора, копирование папки, повторный запуск). Артефакт — ZIP в артефактах и Releases, в git не коммитится.

Ловушки стоимости и переносимости (ST4). .NET: `--self-contained` вкладывает рантайм, trimming и AOT ломают reflection и WPF — проверять запуском, а не сборкой. Go: рантайм не нужен, но GUI-обвязки тянут C-зависимости. Rust: таргет `msvc` даёт самодостаточный EXE, GNU-таргет требует MinGW-рантайм в поставке. Node.js: нативные модули собираются под Windows отдельно, рантайм вкладывать в поставку. C/C++: либо статическая линковка рантайма, либо честная инструкция про бесплатный VC++ Redistributable — молча рассчитывать на него нельзя.

K8.0. Бутстрап окружения (C3.1): после общей части C3.0 проверить наличие инструмента своего стека (`dotnet --info`, `go version`, `cargo --version`, `node -v`, `cmake --version`), отсутствующий поставить из свободного источника, версию показать в выводе. Платный инструмент не покупать. Недоступен — отчёт о причине, код не писать.
