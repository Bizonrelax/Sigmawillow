### LICENSES.md — АТРИБУЦИЯ И ЛИЦЕНЗИИ

A1. Файлы. `THIRD-PARTY-NOTICES.md` в корне — реестр заимствований: источник (URL), автор, что именно взято, лицензия (SPDX), требуемый текст атрибуции, дата обращения. Отдельным разделом — лицензии всех зависимостей своего стека (Maven, pip, npm, cargo, NuGet) с точными версиями. Каталог `licenses/` — полные тексты лицензий. Конвенция та же, что в SaberW и SaberW-2.

A2. Комментарий над заимствованным блоком:

```java
// Source: URL | Author: имя | License: MIT
```

Комментарий делает реестр проверяемым через grep. Удалять комментарии атрибуции запрещено — это юридическое требование, а не читаемость.

A3. Правила заимствования.

| Ситуация | Действие |
| --- | --- |
| Лицензия неизвестна | не копировать; реализовать самому по идее; решение записать |
| Stack Overflow, форумы (CC BY-SA) | по умолчанию не копировать |
| GPL, AGPL, LGPL | не вводить без явного разрешения владельца; зафиксировать отказ |
| MIT, BSD, Unlicense | можно, сохранить копирайт и текст лицензии |
| Apache-2.0 | можно, перенести NOTICE |
| Заимствование из своих репозиториев | записать со ссылкой, лицензия та же |

Идеи не охраняются, конкретный текст кода охраняется.

A4. README. В конце каждой языковой части — раздел Credits / Заимствования: краткий список авторов и источников со ссылкой на `THIRD-PARTY-NOTICES.md`. Полные тексты лицензий в README не вставлять.

A5. Проверка при закрытии. Реестр ↔ комментарии в коде ↔ список зависимостей ↔ разделы README EN и RU. Расхождение = красное, ТЗ не закрывать.

A6. Лицензия своего проекта. Не выдумывать. Есть LICENSE — прочитать и указать в README. Нет — написать «лицензия не задана», зафиксировать в `GVK/AUDIT.md`, работу не блокировать.
