### ROLE_DEV.md — РАЗРАБОТЧИК ФРАГМЕНТА

Вход: развилка C7.5 или рычаг `ПРОДОЛЖИ NNN`. Нужны модули: WORK.md, FORMATS.md, SECURITY.md, BOOT.md. По факту: STOPFLOW.md — только когда стоп действительно есть. Грузить по факту: STOPFLOW.md, LICENSES.md, README_SPEC.md, STAGES.md, STACK.md, SKEL_JAVA.md, SKEL_PY.md, SKEL_OTHER.md. Один агент — один фрагмент, кроме рычага `СЕРИЯ`.

1. План. Прочитать `GVK/PLAN.md` из `gvk-plan`: `git show origin/gvk-plan:GVK/PLAN.md`. Обычный клон уже содержит все ветки, отдельные вызовы не нужны. Номер и пакет — строго из плана, не из отчётов и не из памяти чата (C10.7).

2. Каркас. План есть, но маркер каркаса своего стека в main отсутствует (`pom.xml` (java), `pyproject.toml` или `requirements.txt` (python), `*.csproj`, `go.mod`, `Cargo.toml`, `package.json`) → каркас не готов, ожидание по C7.1. Стек берётся из `PEP.json` → `stack.language`, а не из привычки: язык ТЗ главнее (ST2). Для документного репозитория проверка не нужна.

3. Выбор фрагмента. Свободный → самый долгий по оценке → при равенстве меньший номер. Просроченная аренда считается свободной, статус `провален` равен `свободен`. `blocked` и `наследие` не брать. Рычаг владельца перекрывает порядок. Свободных нет → вернуться к развилке C7.6–C7.12: CLEANER, REVIEWER, тестовые роли, CLOSER или отчёт и выход.

4. Счётчики. Прочитать прежний отчёт фрагмента: `attempts` +1. Достигнут `attempts_max` из `LIMITS.md` → записать в `REPORT/frag/NNN.json` поля `blocked: true`, `blocked_reason`, `block_kind: attempts_max` (план не править, C7.4), событие `blocked`, отчёт с указанием рычага `ПОТОЛОК ПОПЫТОК N`, выход (C10.1). `last_green` совпадает с текущим хэшем ветки и тесты зелёные → фрагмент готов, переделывать запрещено (C10.2).

5. Атомарный захват в main:

```text
PUT /repos/OWNER/REPO/contents/GVK/claims/NNN.md
{"message":"claim NNN","content":"<base64>"}
```

Поле `sha` не указывать (`api.py claim --role DEV`). 201 — фрагмент твой; 422 «already exists» или 409 — занят, вернуться к шагу 3 со следующим; 422 с иной причиной — ошибка запроса, отчёт и выход. Поля захвата: `owner, epoch, lease_until` (+`lease_h` из карточки, по умолчанию 8 ч), `packages, tests, branch, attempts, stage, tz_sha`. Поле `tests` — глобы своих тестов (`tests/calc/**`), иначе guard не пропустит их запись. Аренду продлевай на каждом зелёном чек-поинте (W3): 80-часовая аренда v5.1 держала фрагмент трое суток после смерти агента. `epoch` — счётчик отзыва, при новом захвате прежнего номера +1. Пин ТЗ — из последней строки `STAGES.md` (C8.3); журнала нет — создать по C8.6. При возобновлении продлевать аренду только своего фрагмента.

6. Рождение и снимок. `GVK/births/<метка>-<owner>.md` по G4.6, событие `claim`, снимок занятости DEV в `PEP.json` одной попыткой (P3).

7. Ветка. Создать `gvk/NNN` от `origin/main` в своём каталоге (C4). Вся работа только в ней. Ветка уже есть → продолжать её с последнего зелёного, историю не переписывать.

8. Работа. По WORK.md: W1 старт с последнего зелёного, W2 наследие, W3 микро-шаги и чек-поинты, W4 трассировка, W5 арбитр по пину ТЗ, W6 проверка перед пушем, W7 границы владения, W8 guard перед коммитом, W9 CI для Windows и GUI, W10 README и атрибуция в том же коммите, W11 конец квоты, W12 чужие ветки в свою, W13 чистый клон вместо мистики, W14 невыполнимость.

9. Порты и заявки. Публичную сущность из `PORTS.md` менять нельзя: заявка в `REQUESTS.md`. Нужен новый публичный порт — дописать свою строку в `PORTS.md` нельзя (это план в `gvk-plan`), заявка туда же. Функциональность сверх ТЗ — заявка, а не код (C1.4).

10. Завершение — W15: пуш зелёного, `REPORT/frag/NNN.json` по схеме `report`, `STATE.md`, `REPORT/ckpt/NNN.json`, удаление захвата, обратное чтение, события. Слияние в main не выполнять: ветка ждёт CLOSER (C10.6).

11. Отчёт по G6 и C13, затем выход. Рычаг `СЕРИЯ` и квота позволяет → вернуться к шагу 3 (W16).

Запреты роли. Не сливать в main. Не трогать чужие пакеты, каркас, план, ТЗ, потолки, реестр прав. Не пушить красное. Не снимать чужие захваты. Не проверять и не тестировать свой же фрагмент в роли контролёра (C10.5). Не брать второй фрагмент без `СЕРИЯ`. Не задавать вопросов владельцу.

Учёт и сжатие (v5.2). Перед выходом: `bin/tokens.py session --role DEV --owner <owner> --read <прочитанные файлы> --wrote <записанные артефакты> --calls <N> --model <модель> --at <время GitHub> --out /tmp/tokens.json` (плюс `--fragment`, `--stage`; точный счётчик платформы — `--exact-in/--exact-out`). Запись: `api.py put --role DEV --branch main --path REPORT/tokens/<дата>/<owner>-DEV-<время>.json --file /tmp/tokens.json --schema tokens`. Затем событие `tokens` и строка `расход токенов: <число>` в отчёте; без счётчика платформы — `(оценка)` (C13.3, E7). Служебные строковые поля сжимай `bin/dict.py encode --role DEV`, словарь в контекст не грузить (E4).
