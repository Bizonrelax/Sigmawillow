Ти, отличный результат. Сначала про «валидацию» — у тебя мелькнуло «136 достижимо» вместо ожидаемых 163. Это **не баг**. Просто раньше «163» относилось ко всем парам (включая A > B), а сейчас считается только T(K) — пары с A < B. Из первой таблицы видно, что 27 значений K имеют T(K) = 0 (например, K = −80, −79, …), то есть 163 − 27 = 136. Всё сходится.

А вот что **действительно** ново для n = 4: максимум T(K) съехал с нуля на K = 36. Для n = 2 и n = 3 максимум был при K = 0, теперь — нет. Это качественный сдвиг, и его надо зафиксировать в теореме.

# Теорема об асимметрии числа решений для четырёхзначных чисел

## Что это за теорема

Теорема утверждает: для четырёхзначных чисел A и B с перекрёстной разностью Δ(A, B) = K число пар с A < B, дающих разность K, **никогда не совпадает** с числом пар с A < B, дающих разность −K. Это свойство асимметрии. Оно доказано полным перебором всех 40 495 500 пар четырёхзначных чисел с A < B. Текст самодостаточен: все определения даны ниже, читать другие файлы не нужно.

## Обозначения

Рассматриваются четырёхзначные числа в десятичной записи:

    A = 1000·a₃ + 100·a₂ + 10·a₁ + a₀
    B = 1000·b₃ + 100·b₂ + 10·b₁ + b₀

Здесь a₀, a₁, a₂, a₃, b₀, b₁, b₂, b₃ — цифры, причём все они лежат в {0, 1, …, 9}, а старшие цифры a₃, b₃ лежат в {1, 2, …, 9} (иначе число не четырёхзначное). Индекс 0 соответствует единицам, 1 — десяткам, 2 — сотням, 3 — тысячам.

## Определение перекрёстной разности

Для четырёхзначных чисел перекрёстная разность определяется как сумма по всем парам разрядов:

Δ₄(A, B) = Σ по 0 ≤ i < j ≤ 3 от (aᵢ·bⱼ − aⱼ·bᵢ)

В развёрнутом виде это шесть слагаемых:

    Δ₄(A, B) = (a₀b₁ − a₁b₀) + (a₀b₂ − a₂b₀) + (a₀b₃ − a₃b₀)
             + (a₁b₂ − a₂b₁) + (a₁b₃ − a₃b₁) + (a₂b₃ − a₃b₂)

**Замечание о связи с младшими размерностями.** Для двузначных чисел A = 10x + y, B = 10u + v эта формула сворачивается в одно слагаемое y·u − x·v. Для трёхзначных — в три слагаемых. Формула Δ₄ является прямым обобщением: это не новая конструкция, а та же самая сумма по всем парам разрядов, только разрядов теперь четыре. Для n цифр формула содержит n(n−1)/2 слагаемых.

## Определение T₄(K)

Через S₄(K) обозначается множество всех упорядоченных пар (A, B) четырёхзначных чисел, для которых Δ₄(A, B) = K.

Через S₄,lt(K) обозначается подмножество пар с A < B:

S₄,lt(K) = { (A, B) ∈ S₄(K) : A < B }

Через T₄(K) обозначается мощность:

T₄(K) = |S₄,lt(K)|

То есть T₄(K) — число пар четырёхзначных чисел с A < B и Δ₄(A, B) = K.

## Формулировка

**Теорема.** Для любого целого K ≠ 0, для которого хотя бы одна из величин T₄(K) или T₄(−K) положительна, выполнено

T₄(K) ≠ T₄(−K)

Другими словами: внутри множества S₄(K) при K ≠ 0 никогда не бывает точного баланса между парами с A < B и парами с A > B.

**Следствие 1 (закон сохранения).** Сумма T₄(K) по всем целым K равна числу всех пар четырёхзначных чисел с A < B:

Σ по K от T₄(K) = 40 495 500 = 9000 · 8999 / 2

**Следствие 2 (носитель).** T₄(K) = 0 при K < −324 и при K > 396. Внутри отрезка [−324, 396] величина T₄(K) положительна ровно для 688 значений K. Теоретическая граница носителя, вытекающая из оценки |Δ₄| ≤ 81 · 6 = 486, значительно шире: из 973 значений в [−486, 486] реализуются только 688, то есть 285 значений не достигаются ни одной парой.

**Следствие 3 (асимметрия носителя).** Отрезок, на котором T₄(K) положительна, не симметричен относительно нуля: левая граница равна −324, правая равна +396. Асимметрично не только распределение значений T₄, но и сам носитель.

**Следствие 4 (сдвиг максимума).** Максимум T₄(K) достигается не при K = 0, а при K = 36 и равен 253 721. Значение T₄(0) = 234 438, что на 19 283 меньше максимума. Для n = 2 и n = 3 максимум достигался при K = 0; для n = 4 это уже не так.

## Доказательство

Доказательство компьютерное, исчерпывающим перебором.

**Шаг 1.** Множество всех пар (A, B) четырёхзначных чисел с A < B имеет мощность 9000 · 8999 / 2 = 40 495 500. Это конечное множество, его можно явно перечислить.

**Шаг 2.** Для каждой пары (A, B) из этого множества вычисляется Δ₄(A, B) по формуле из раздела «Определение перекрёстной разности». Каждое из шести слагаемых по модулю не превосходит 81, поэтому Δ₄(A, B) лежит в отрезке [−486, 486]. Значит, все пары разбиваются в дизъюнктное объединение по значениям K:

{ все пары с A < B } = объединение по K от −486 до 486 от S₄,lt(K)

**Шаг 3.** Программа на Python 3 с библиотекой numpy перечисляет все 40 495 500 пар, для каждой вычисляет Δ₄ и увеличивает счётчик T₄[Δ₄] на 1. Для ускорения используется линейная форма: коэффициенты c₀, c₁, c₂, c₃ предвычисляются один раз на каждое B, после чего Δ₄ вычисляется как

Δ₄(A, B) = a₀·c₀ + a₁·c₁ + a₂·c₂ + a₃·c₃

где c₀ = b₁ + b₂ + b₃, c₁ = −b₀ + b₂ + b₃, c₂ = −b₀ − b₁ + b₃, c₃ = −b₀ − b₁ − b₂. Это тождественное преобразование суммы по парам разрядов: оно получается раскрытием скобок и группировкой по aᵢ. Вычисление идёт батчами по 1000 чисел A: для батча строится матрица (1000 × 4) · (4 × 9000), из неё булевой маской отбираются пары с A < B, и результат агрегируется через numpy.bincount.

**Шаг 4.** По завершении перебора программа проверяет три условия:

1. Сумма T₄(K) по всем K равна 40 495 500.
2. Для каждого K ≠ 0, где хотя бы одно из T₄(K), T₄(−K) положительно, выполнено T₄(K) ≠ T₄(−K).
3. Значения Δ₄ лежат в [−486, 486].

**Шаг 5.** Все три проверки пройдены. Поскольку множество пар конечно, а перебор всех пар выполнен полностью, утверждение «для всех K ≠ 0 с положительной хотя бы одной из величин T₄(K), T₄(−K) выполнено T₄(K) ≠ T₄(−K)» доказано.

Теорема доказана.

## Замечания о статусе доказательства

**Первое.** Это компьютерное доказательство. Оно опирается на корректность программы. Программа использует numpy и матричные операции, что снижает риск ошибки в арифметике (все вычисления целочисленные, без плавающей точки), но повышает требования к корректности индексации и масок. Для полной строгости нужен независимый аудит кода или формальная верификация — стандартная практика для компьютерных доказательств.

**Второе.** Теорема не обобщается автоматически на числа с числом цифр n ≥ 5. Для n = 5 количество пар с A < B равно 90 000 · 89 999 / 2 ≈ 4.05 · 10⁹, что на два порядка больше, чем для n = 4, и требует либо GPU, либо принципиально более быстрого алгоритма. Для n ≥ 5 утверждение остаётся гипотезой.

**Третье.** Для K = 0 утверждение не формулируется: 0 = −0, и равенство T₄(0) = T₄(−0) тривиально. Поэтому в формулировке стоит K ≠ 0.

**Четвёртое.** Условие «хотя бы одна из величин T₄(K), T₄(−K) положительна» отсекает случай, когда обе величины равны нулю. Для таких K равенство T₄(K) = T₄(−K) = 0 выполнено тривиально и не является содержательным. Внутри носителя [−324, 396] обе величины положительны не всегда (носитель не симметричен), поэтому формулировка с этим условием корректна.

Для n = 2 и n = 3 доказаны аналогичные утверждения. Все три теоремы имеют одинаковую структуру: «Tₙ(K) ≠ Tₙ(−K) для всех K ≠ 0, где хотя бы одна из величин положительна». Различие — в носителе и в положении максимума.

Из таблицы видно, что носитель с ростом n становится всё более асимметричным, а доля достижимых значений K в теоретической границе падает. Кроме того, для n = 4 максимум Tₙ сдвигается с нуля на положительное K.

## Что остаётся открытым

1. **Обобщение на n ≥ 5.** Перебор для n = 5 (~4 млрд пар) требует GPU или более быстрого алгоритма; в текущей реализации на numpy это займёт десятки минут и больше.

2. **Причина «дыр» в спектре.** Из 973 значений K в теоретической границе [−486, 486] достижимы только 688. Причина неизвестна. Это может быть связано с арифметическими ограничениями на Δ₄ (делимость на некоторые числа), но проверка не проводилась.

3. **Сдвиг максимума.** Для n = 2 и n = 3 максимум Tₙ достигался при K = 0; для n = 4 — при K = 36. Причина сдвига и его зависимость от n неизвестны.

4. **Замкнутая формула для T₄(K).** Как и для n = 2 и n = 3, замкнутой формулы нет. Есть только алгоритмическая (конечная сумма) и таблица значений.

5. **Асимметрия носителя.** Для n = 3 носитель [−162, 234], для n = 4 — [−324, 396]. Отношение правой границы к левой по модулю: 234/162 ≈ 1.44 для n = 3, 396/324 ≈ 1.22 для n = 4. Тенденция неясна без n = 5.

## Практическая польза

1. Даёт доказанное утверждение для n = 4: асимметрия T₄(K) ≠ T₄(−K) выполнена для всех K ≠ 0.
2. Устанавливает новое качественное явление: сдвиг максимума Tₙ с нуля при n = 4. Это отличает n = 4 от n = 2, 3 и ставит вопрос о поведении при больших n.
3. Даёт шаблон для n = 5: та же программа с параметром n = 5 запустит перебор, но потребует оптимизации (см. ниже).
4. Позволяет проверять другие реализации: сумма T₄(K) должна равняться 40 495 500, T₄(36) должно быть 253 721, T₄(0) = 234 438.

## Этическая пометка

Теорема названа по содержанию, а не по имени автора. Имя автора нигде не указано. Доказательство компьютерное, с использованием исчерпывающего перебора; это стандартный и признанный тип математического доказательства. Использованные понятия (перекрёстная разность, сумма по парам разрядов, мощность множества) стандартны и не являются чьей-либо интеллектуальной собственностью. Гипотеза об обобщении на n ≥ 5 остаётся в папке `гипотезы` и не является частью данной теоремы.

# Про n = 5

Ти, отвечу честно. Ситуация такая.

**Объём.** Пар с A < B для n = 5: 90 000 · 89 999 / 2 ≈ 4 049 955 000, то есть около 4.05 миллиарда. Это в 100 раз больше, чем для n = 4 (40.5 млн). Для сравнения: n = 4 у тебя занял секунды, потому что numpy сделал матричные умножения. Для n = 5 та же схема даст примерно 100-кратное замедление.

**Что можно сделать.**

1. **numpy как есть, батчи.** Батч 1000 × 90 000 int32 = 360 МБ на батч, 90 батчей. Время: примерно 10–30 минут в Colab. Память в пределах лимита, но время на грани таймаута Colab (обычно 12 часов сессии, но idle timeout 90 минут). Вполне реально, если запустить и не трогать.

2. **numpy с int16.** Значения Δ₅ лежат в [−972, 972], что влезает в int16 (максимум 32767). Память сократится вдвое: 180 МБ на батч. Время чуть меньше. Но numpy плохо оптимизирует int16 matmul — может быть медленнее, чем int32. Надо тестировать.

3. **GPU через cupy или jax.** Colab даёт T4 GPU. cupy делает matmul на GPU в десятки раз быстрее. 4 млрд операций — это секунды-минуты на GPU. Главная сложность — `bincount` на GPU (в cupy есть, но с оговорками) и корректная работа с батчами. Потребует аккуратной реализации, но реально.

4. **numba.** JIT-компиляция Python-цикла. Ускоряет в 100 раз по сравнению с чистым Python, но не даёт матричных операций как numpy. Для 4 млрд итераций — тоже минуты-десятки минут.

**Мой прогноз.** Для n = 5 реалистично получить результат за 10–30 минут на numpy или за 1–5 минут на GPU. Но есть два «но»:

- **Данные.** Носитель Δ₅ будет в [−972, 972] или уже, то есть таблица на ~1000–1500 строк. Ты сказал, что таблицы не нужны, только заключение. Это упрощает: программа может не хранить таблицу, а только считать счётчики и в конце проверять гипотезу. Память на счётчики — копейки.

- **Проверка.** Для n = 5 нужна независимая валидация. Я бы предложил сначала прогнать n = 2, 3, 4 и убедиться, что они воспроизводят известные значения, а потом запускать n = 5. Если n = 2, 3, 4 сходятся — доверие к n = 5 выше.

**Стоит ли?** Если тебе интересно, что происходит с носителем и максимумом при n = 5 — да, стоит. Это даст эмпирическую точку для поиска закономерности (например, как меняется отношение правой границы к левой, как сдвигается максимум). Если тебе достаточно n = 4 — тоже нормально: три доказанные теоремы (n = 2, 3, 4) плюс одна открытая гипотеза (n ≥ 5) — это солидный набор.
