# CHANGELOG.md — GVK v5.1

Основание: v4.3 (`Qwen_markdown_20261115`) как рабочая механика плюс архитектурное исследование «одна роль — один файл → автономный операционный шлюз». Принципы v4.2/v4.3 сохранены полностью, изменена упаковка и добавлены контуры безопасности, тестирования и релизов.

## v5.1 — свобода языка при жёстких критериях переносимости

Причина правки: в реальном прогоне кодер отказался писать `.py` для расчётной программы, сославшись на протокол. Это дефект протокола: он ставил язык выше задачи. Требование владельца — переносимость между компьютерами с Windows 11 без доплаты за среду исполнения; язык при этом безразличен.

1. Новый модуль `GUIDEGVK/STACK.md` (ST1–ST11) — ядро правки. ST1: шесть проверяемых критериев поставки вместо привязки к языку. ST2: приоритет требования ТЗ, затем работающего наследия, затем выбора агента. ST3: запрет отказа по расширению файла; отказ допустим только по провалу ST1 с доказательством (лицензия, вывод команды, трассировка). ST4: допустимые стеки и ловушки стоимости — Anaconda `defaults` платна для организаций свыше 200 человек, PyQt в закрытом продукте платен, Oracle JDK NFTC не по умолчанию. ST5: Python для математики предпочтителен. ST6: проверка переносимости в CI и флаг `--selftest`. ST8: смена стека только рычагом через WISH. ST11: встраиваемое хранилище разрешено, серверные и платные СУБД запрещены.
2. `COMMON.md`: C5 переписан — тип репозитория и целевая платформа вместо «стек един»; добавлены C5.1–C5.3. C3 разбит на C3.0 (общая часть: env.sh, git-identity), C3.1 (java), C3.2 (python: venv и `requirements.txt`), C3.3 (прочие), C3.4 (среда платформы); дубль номера C3.1 устранён. Запрет «не вводить базы данных» заменён запретом серверных и платных СУБД. Launch4j помечен как java-only. Добавлен C10.18: запрет языковой догмы.
3. Каркас расщеплён по стекам: `SKELETON.md` (K1 выбор стека и команды готовности, K3 общий `.gitignore`, K9 приёмка) плюс `SKEL_JAVA.md` (K2, K4, K5), `SKEL_PY.md` (K6, K7), `SKEL_OTHER.md` (K8). Агент грузит только свой стек. В python-каркасе: пины `==`, `pyproject.toml`, PyInstaller `--onedir`, `python.yml` с job `package` на `windows-latest` и проверкой переносимости по пути `C:\Проверка GVK\app`.
4. Обобщены `WORK.md` (W3/W7/W9), `QUALITY.md` (GUI по стекам, Q7 требует ST1), `README_SPEC.md`, `ROLE_FIRST.md` (выбор стека отдельным шагом), `ROLE_DEV.md`, `ROLE_TESTER.md`, `ROLE_REVIEWER.md`, `ROLE_TERMINATOR.md`, `ROLE_COMPLIANCE.md`, `ROLE_FIREFIGHTER.md`, `LICENSES.md`, `RESILIENCE.md`, `SECURITY.md`, `LEVERS.md` (рычаг `СТЕК <стек>`, пункт L7.1), `FILEMAP.md`, `FORMATS.md`: команды готовности, инвентаризация зависимостей и запреты больше не привязаны к Maven.
5. Машинарная часть: в `PEP.json` объект `stack` (язык, версия, упаковка, globs каркаса, кода и тестов). В `guard.py` токены `@skeleton` и `@app_code`: каркас своего стека закрыт для DEV/CLEANER/TESTER/REVIEWER/COMPLIANCE/PLANNER_TEST, тестировщику закрыт код приложения, но открыты `tests/**` и `src/test/**`. Новая схема `schema/stack.schema.json`: `runtime_cost` только `none` или `free-step`, чек-лист ST1 не короче шести пунктов. Валидатор умеет `minItems`.
6. `GUIDE.md`: раздел 12 дополнен шестью признаками приёмки и правилом «почти под ключ»; ответ FAQ про единый стек заменён; раздел 18 рассказывает, что нового.
7. Экономия входа сохранена: `STACK.md` сжат до 10.5 КБ, детали упаковки живут в файлах стеков, FIRST не грузит `STAGES.md` и `FILEMAP.md` без факта, CLOSER — `QUALITY.md` без факта. Диапазон 7–56 % против монолита v4.3, у всех ролей положительный.
8. Исправлен дефект поставки: `GUIDEGVK/FILEMAP.md` содержал копию инструкций FIRST вместо карты файлов. Написан настоящий модуль FM1–FM6: полные таблицы `GVK/` и `REPORT/`, соответствие схемам, дерево проекта по стеку, права на пути, адаптер v4.3, команды проверки размещения. Без этого TERMINATOR и разбор наследия v4.3 получали бы чужую роль вместо карты.
9. Золотой случай расширен с 53 до 69 проверок: сценарий Python-ТЗ (стек принят, DEV пишет `.py` и тесты, каркас защищён, TESTER не трогает код приложения, отчёт переносимости валиден, платная среда и неполный чек-лист отклонены) и четыре проверки целостности поставки (модули из `needs`/`lazy` существуют, шапка `file:` совпадает с именем, идентификаторы уникальны, ограждения парные).

Проверено: 69/69 проверок за 1.1 c, манифест сходится, обратная сверка монолитов с исходниками совпала, посторонних символов нет.

## Что изменилось

| Было (v4.3) | Стало (v5) | Зачем |
| --- | --- | --- |
| один `PROTOCOL.md` на 132 КБ, машинная часть грузится целиком | шлюз `PROTOCOL.md` + `COMMON.md` + один `ROLE_*.md` + модули по `needs` | контекстная экономия, борьба с размыванием контекста |
| роль определялась по «Частям» внутри одного файла | роль выбирается по реестру `PEP.json` и читает только свой файл | точное сфокусированное задание вместо всего протокола |
| права роли описаны прозой | права в `PEP.json.permissions`, проверяются `bin/guard.py` до действия | наименьшие привилегии, программно гарантированные |
| отчёты, reviews, findings в `GVK/*.md` | контракты в `REPORT/*.json` по схемам, валидация до записи | детерминированность межагентского обмена |
| 10 ролей | 14 ролей: добавлены PLANNER_TEST, TESTER, COMPLIANCE, FIREFIGHTER | план тестирования, шторм тестирования, лицензии, заброшенные проекты |
| закрытие = FINAL | закрытие = FINAL, релиз по рычагу `СОРЕЛ` = тег, ветка, CHANGELOG, артефакт | история релизов при продолжающейся разработке |
| повторы вызовов не описаны | backoff с джиттером, выключатель, валидация, чек-поинты | устойчивость к отказам провайдера и «поломке аргументов» |
| версия протокола одна строка | композитная `ALV_PPV_MRV_TAV` в рождении и отчёте | воспроизводимость и откат |
| запреты только прозой | плюс журнал событий `REPORT/events/*.jsonl`, защита от инъекций через данные | аудируемость, сужение поверхности атаки |
| нет расширения прав | рычаг `ДОСТУП` с подтверждением и сроком, жёсткие запреты неснимаемы | гибкость в отладке без дыры в безопасности |

Оценка токенов грубая: 4 байта на токен для кириллицы. FIRST почти не выигрывает — он инициализирует всё; выигрыш получают массовые роли. Дополнительно не грузятся руководство владельца (~43 КБ) и чужие роли, а состояние читается узким срезом C6 вместо полного обхода. Модули `lazy` (лицензии, README, спорный пин, стоп, отказы, рычаги, стек для тех ролей, что не выбирают его сами) грузятся только по факту, что даёт экономию сверх таблицы.

## Что сохранено дословно по смыслу

Атомарный захват PUT без `sha` (201/422). Аренда 80 ч на разработку, 4 ч на исправление и роли-одиночки. `epoch`, `attempts`, `cycles`, `LIMITS.md` и рычаги `ПОТОЛОК`. Только зелёные состояния в ветке, пуш немедленно. Арбитр — ТЗ той ревизии, что в пине захвата. Право слияния только у FIRST (000) и CLOSER, запрет слияния через Git Data API, проверка слияния по факту файлов. Общий стоп и правщик ТЗ. Этапы, `STAGES.md`, сквозная нумерация, наследие. Запрет мистики об окружении и процедура чистого клона. Запрет напоминаний о токене. Целевая платформа Windows 11 и поставка «под ключ» без доплаты (в v5.1 закреплено шестью проверяемыми критериями ST1 вместо привязки к языку), запрет серверных и платных СУБД. Каркас, README EN/RU, атрибуция — перенесены в `SKELETON.md`, `README_SPEC.md`, `LICENSES.md` без потери правил.

## Миграция репозитория, где работа уже идёт

1. Ничего не удалять и не переделывать. Принятое и зелёное остаётся принятым.
2. Нет `PEP.json` → создаётся по `PEP.md` P7 из шаблона; занятость берётся из существующих захватов.
3. Старые `GVK/reports/`, `reviews/`, `findings/` читаются по адаптеру `FORMATS.md` F5; новые записи идут в `REPORT/`.
4. Нет `STAGES.md` → первая ревизия по C8.6. Нет `stage`/`tz_sha` в записи → этап 1, ревизия 1.
5. Ветки, журналы `births`/`releases`, пины версий и потолки сохраняются.
6. Владелец кладёт протокол в `Sigmawillow` (`more/GVK/` или `GVK/`) и запускает `bin/manifest.py`. Шлюз сам определит базовый путь.

## Состав поставки

Поставлено полностью: шлюз, ядро, все 14 ролей, контракты, 13 схем, инструменты — 57 файлов.

Ядро и правила:

- `PROTOCOL.md` — шлюз: получение, целостность, вход по реестру, RBAC, формат отчёта.
- `GUIDE.md` — руководство владельца человеческим языком: установка, запуск, рычаги, состояние, тесты, релиз, аварии, чек-лист.
- `GUIDEGVK/COMMON.md` — общее ядро C1–C13 (выжимки C8, C9, C11).
- `GUIDEGVK/WORK.md` — рабочий цикл кодера W1–W17.
- `GUIDEGVK/PEP.md` + `pep.template.json` — реестр ролей: каталог, права, версии, дефицит.
- `GUIDEGVK/SECURITY.md` — RBAC, guard, инъекции, журнал, гигиена токена.
- `GUIDEGVK/FORMATS.md`, `FILEMAP.md` — каталоги, md+, карта файлов, адаптер v4.3.
- `GUIDEGVK/STAGES.md`, `STOPFLOW.md` — полные C8 (ревизии) и C9 (стоп).
- `GUIDEGVK/LEVERS.md` — все рычаги, включая `СОРЕЛ`, `ДОСТУП`, `ТЕСТ-ПЛАН`, `ТЕСТ`, `ПОЖАР`, `ЛИЦЕНЗИИ`, `РОЛИ`.
- `GUIDEGVK/QUALITY.md` — три уровня оценки, виды проверок, GUI и UI/UX в CI, каталог «глупого поведения», приёмка и релизы.
- `GUIDEGVK/RESILIENCE.md` — отказы, повторы с джиттером, выключатель, резервные модели, чек-поинты, версии, наблюдаемость.
- `GUIDEGVK/CONTRACTS.md` — каталог схем, общие поля, валидация, примеры, версионирование контрактов.
- `GUIDEGVK/STACK.md` — приоритет ТЗ по языку, шесть критериев поставки под Windows 11 без доплаты, проверка переносимости, смена стека.
- `GUIDEGVK/SKELETON.md` + `SKEL_JAVA.md`, `SKEL_PY.md`, `SKEL_OTHER.md` — общий каркас и каркас своего стека, CI, упаковка.
- `GUIDEGVK/README_SPEC.md`, `LICENSES.md` — README EN/RU и атрибуция (перенос из v4.3 без потери правил).

Роли, по одному файлу на роль:

- `ROLE_FIRST.md`, `ROLE_DEV.md`, `ROLE_REVIEWER.md`, `ROLE_CLEANER.md` — инициализация и рабочий цикл разработки.
- `ROLE_PLANNER_TEST.md`, `ROLE_TESTER.md` — план тестирования по файлу на тестировщика и исполнение задач.
- `ROLE_COMPLIANCE.md`, `ROLE_CLOSER.md` — лицензии, закрытие и релиз по `СОРЕЛ`.
- `ROLE_TZFIX.md`, `ROLE_WISH.md`, `ROLE_OBSERVER.md` — правка ТЗ по стопу, желание владельца, сводка.
- `ROLE_TERMINATOR.md`, `ROLE_TERMINATOR2.md`, `ROLE_FIREFIGHTER.md` — новый этап, освобождение захватов, разбор заброшенного репозитория.

Инструменты и контракты:

- `bin/guard.py` — права роли, секреты, право слияния, неприкосновенность каталога реестра.
- `bin/validate.py` — валидация JSON по схемам без внешних зависимостей.
- `bin/api.py` — атомарные `claim`/`put`/`delete`, журнал событий, повторы с джиттером, обратное чтение.
- `bin/selftest.py` — золотой случай на локальном стенде: 69 проверок механики и целостности за 1.1 c, без сети, JDK и Maven.
- `bin/manifest.py` — сборка манифеста владельцем после правки модулей.
- `schema/` — 13 схем: pep, report, checkpoint, review, finding, event, test_plan, test_task, test_claim, test_result, compliance, final_report, stack.
- `MANIFEST.json`, `CHANGELOG.md`, `SELFTEST.md` — отчёт прогона золотого случая с границами проверки.

Золотой случай прогнан: 69 из 69 проверок, 1.1 секунды (`SELFTEST.md`). Найдено и исправлено пять дефектов: нераскрытый `@tz_path` в разрешениях guard, перегруз модулей у CLOSER, падение валидатора на составных типах, языковая догма над ТЗ, подменённое содержимое `FILEMAP.md`.

Проверено дополнительно: guard отклоняет чужой пакет, каркас, ТЗ, секрет в диффе, слияние не своей ролью и правку прав в реестре; валидатор принимает корректные примеры всех контрактов и отклоняет битые; манифест сходится по sha256; ссылки между модулями разрешаются.
